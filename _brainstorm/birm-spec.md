# BIRM — Buildable Spec

**Status: §1–§10 all carry ledger rows.** R4 is satisfiable and the organ and bus statuses in §3 and §4 are lifted accordingly. A section with no ledger rows is not "done", it is "asserted". What §10 licenses is bounded by §10.5, and the two sections must be read together: **§10 can refute; it cannot license** — the claim rests on §2.2's declared priors and §11's ledger of decisions, not on a score.

> **What this document is.** One buildable specification of BIRM: an agent-side controller that receives observation vectors and emits action vectors, with everything benchmark-specific pushed into an adapter. It is written so that a later reading wave can *replace* a filled cell rather than append to it — see §11's `Supersedes` column and §13.
>
> **What it is not.** Not a literature review (that is `wiki/`), not a wish list (that is `wiki/architectural-gaps.md`). A row belongs here only if it is implementable as written or explicitly marked `OPEN-SLOT` in §12.

## 1. Scope

| Slot | Fill |
|---|---|
| Target task set (three-component framing: name it or No-Free-Lunch applies) | The **interactive, transition-sampled slice of the abstract-reasoning AI Set**: an agent emitting actions into an environment family, recovering structure from `(obs, action, obs')` triples. In the latent-variable bit-vector: **edge existence, edge label, path and goal node latent**; node content given by the adapter. **The edge vocabulary's size is not given**: BIRM receives an index into an action code of width `k`, and `k` is the adapter's *encoding* of the repertoire, not a count of the family's edge labels. `k` is charged at `H2` and `H10` and never read as knowledge of the graph. **General rule:** anything solvable by a series of reasoning steps can be adapted into an agent emitting actions into an environment family, with structure recovered from `(obs, action, obs')` triples; how `o` and `a` come to be is the adapter's responsibility. The interactive slice is BIRM's **chosen instantiation**, not a claim about which problems have this shape. Static input→output formats instantiate the rule through an adapter supplying a deterministic `apply(a, o) → o'` plus an authored vocabulary, edge-label-latent becoming path-latent. `D2`, `D129`, `D130` |
| Benchmarks that instantiate it | Primary: `[[wiki/entities/arc-agi-3.md]]` — interactive, action semantics and goal both withheld, and its scoring function `S = min(h/a, 1.15)²` is already the efficiency ratio rather than a side column. Secondary: a **repurposed-skill family** (train on game `X`, evaluate on unpublished variants `X₁…Xₙ` built so `X`'s optimal program is not optimal for `Xᵢ`) — the environment-family identifiability condition turned into an instrument. Control: an **arbitrary sensorimotor mapping** task at `k ≥ 3` alternatives. `D3` |
| Explicitly out of scope — **one kind only** | **(v) Unambiguously-observed environments**: families in which `o_t` identifies the latent state on its own. There, aliasing is absent, `g` has nothing to compensate for, and the belief code this spec is built around is not needed. **Intermediate observation ambiguity is a precondition of the task set, not a hazard of the encoding.** This is the *only* exclusion by problem type; it is `MEASURED` (`D84`) and it is **per-adapter, not per-benchmark**. Static input→output formats (ARC-AGI-1/2, PGM, Raven) are **in scope**: an adapter carrying a deterministic `apply(a, o) → o'` re-encodes them inside the taxonomy, and what that adapter installs is charged as `H10`; a given instance may still fall out under (v), since a fully-rewritten observation *is* the state. Natural language is excluded at §2.1 by the stream contract. The non-embeddable symbolic slice and rewrite-search sit in the non-goals row below. `D84`, `D126` |
| Success statement (one sentence, falsifiable) | On held-out instance-graphs of a **seen** environment family, BIRM reaches skill threshold `θ` in fewer environment steps than a flat baseline of matched parameter count, **and** its advantage survives when performance is plotted against *nodes visited* rather than *edges taken* — the `O(E) → O(V)` gap being the operational definition of "it has the meta-graph". `D5` |
| Non-goals inherited from wiki (things known unbuildable today) | **Constructing the problem representation** — deciding what gets to be a variable (`G73`) — and **choosing a parse** of the input (`G75`): both supplied by the adapter and charged in §2.2. **Deriving the agent/world boundary** (`G92`): drawn by hand, declared, not inferred. **A computable `GD`** (`G31`): approximated in §10, never computed. **In scope by problem type, unmechanised in fact:** the **non-embeddable symbolic slice** (`G11`, `OPEN`, hardness 10) and **rewrite-search** (`T229`) — BIRM has no mechanism for either. `D6`, `D126` |

**Where the narrowing lives** (`D126`). §1 narrows the task set by problem type only under (v); the No-Free-Lunch obligation is discharged in **§2.2, not §1**. An adapter that authors its own action vocabulary, or re-granulates one it was handed (`H10`), carries a strictly larger denominator than one passing the environment's primitives through at the granularity it received them. A broad §1 is read together with an itemised §2.2.

**Scoring discipline forced by the task set** (not optional; `D7`):

| Rule | Statement |
|---|---|
| S1 | A score is a property of **(approach, compute budget)**. Cost per task appears on every reported line or the line is void. |
| S2 | No benchmark with a **data generator** for the evaluation set; the experience term `E` is capped and reported. |
| S3 | The evaluation family is a **depleting stock**. The set used for intermediate/diagnostic scoring is disjoint from the set used for final scoring, and the number of times each has been read is logged. |

## 2. Boundary declaration — BIRM vs. adapter

> The agent/world boundary is drawn by hand (`G92`), and whatever is placed in the adapter is the part of the problem that was *not solved*. An undeclared adapter makes every score in §10 uninterpretable.

### 2.1 Adapter contract

| Interface | Spec | Fixed across benchmarks? |
|---|---|---|
| Observation stream(s): count, dimension, rate, dtype, value range | **One** stream. `o_t ∈ ℝ^{D_o}`, float32, range `[0,1]`, exactly one vector per environment step. `D_o` is a per-benchmark constant declared in §2.2, never inferred and never varying within a family. `D8` | Contract fixed; `D_o` **not** fixed — it is hardwiring `H1` |
| Action code: dimension, discrete/continuous, emission rate | **Discrete**, one-hot over `k` primitives, one emission per environment step, no no-op suppression. `k` declared per benchmark. The *semantics* of each primitive are latent to BIRM — the adapter passes indices, never labels, and BIRM is never told what `k` counts (`D129`): the same repertoire admits many widths, so `k` is an encoding width and not the family's branching factor. `D9` | Contract fixed; `k` **not** fixed — hardwiring `H2` |
| Primary affect channel (the "kickstarter") — signal, range, latency | Scalar `r_t ∈ [−1, 1]`, delivered on the **same step** as `o_t`, no shaping, no per-benchmark rescaling. Deliberately *one* scalar with **no address**: it cannot name what it is about. **Two consumers at two orders** (`D70`): `V` reads it per step (addressed by `L_part`, §4), and `N` reads its *running statistics* as a standing disposition — a multiplicative gate on whether a class of computation is run at all, not a term added to the return | Yes |
| Episode/reset signalling | Explicit boolean `done_t` on the same step. BIRM carries **no state across `done`** except slow weights `W` — the fast store `S` and the structural code `g` are re-initialised, `g` to a **random phase** so a new environment de-aliases against all previous ones. `D11` | Yes |
| **What BIRM assumes about the stream** — not rules imposed on the adapter | BIRM is written as if: (a) the observation is **unparsed** — no objects, entities or slots are marked in it; (b) **no goal signal** arrives, and nothing beyond `r_t` correlates with distance to one; (c) **no action semantics** arrive — no labels, grouping or mask; (d) `D_o` and `k` **do not vary** within a declared family; (e) **no state crosses `done`**; (f) the stream is **not re-ordered, filtered or denoised**. How an adapter arranges to satisfy these is its own business and outside this spec. A family whose adapter cannot satisfy them is out of scope under `D4`, not a spec failure. `D83`. <br><br>**Natural language, as either input or output, is excluded here rather than in §1** (`D126`, re-siting `D4`(iii)): it is not a claim that language is a different problem type, but that a language channel cannot meet (a) unparsed and (d) fixed `D_o` under `D8`, and imports a prior §2.2 has no way to itemise — so any score quoted over it is uninterpretable under S4. | — |

### 2.2 Declared-hardwiring ledger (mandatory)

Every bit of task knowledge that lives outside the learner, itemised. This is the denominator of every claim in §10.

> **The conservation law that makes this section load-bearing.** Relational content is conserved between *inside a unit* and *between units*: enlarging the units deletes edges by swallowing them, shrinking them multiplies edges without adding information. The choice does **not** converge as granularity is refined. So whatever discretisation the adapter imposes has already absorbed an unmeasured part of the graph BIRM is scored on discovering. `H3` is therefore the denominator of the whole spec, and it is currently unquantified. `D13`

| # | Hardwired thing | Where it lives | Why it cannot be learned | Bits/parameters |
|---|---|---|---|---|
| H1 | Observation dimension `D_o`, dtype, value range | adapter | Fixing the stream's width is prior to any learning over it | `?` — §12 `O1` |
| H2 | Action code **width** `k` (semantics excluded) | adapter | The agent cannot emit an action it has no code for; the code width must precede the first step | `log₂ k` per step, plus `k` declared once. **Not a measurement of the family** (`D129`): `k` is what the adapter's encoding chose, and *which* repertoire it chose at *which* granularity is `H10` |
| H3 | **The discretisation implicit in the encoding** — what counts as one observation, and therefore what counts as one node | adapter | Nothing in the wiki constructs a representation (`G73`) or chooses a parse (`G75`); this spec does not attempt it | `?` — **unquantified and load-bearing**; §12 `O2`. Partially *measurable*: `D71` installs a second, agent-side discretisation whose criterion comes from outside the observation stream, so the residual is the composition of the two rather than one opaque choice |
| H4 | Episode boundaries (`done_t`) | adapter | An episode boundary is a claim about which experiences may bind together; it is not recoverable from the stream at the rate BIRM would need it | 1 bit/step |
| H5 | Existence and sign convention of the affect channel `r_t` | adapter | The agent cannot derive that a scalar is *good* from the scalar itself | 1 scalar/step + sign convention |
| H6 | The **structural code's manifold topology** (which group the action displacements act in) | BIRM | Assumed by the designer, not learned — see §6 | `?` — §12 `O3` |
| H7 | Two-timescale split: which parameters are slow `W` and which are fast `M` | BIRM | The split is a sample-complexity decomposition chosen in advance; nothing in the wiki discovers it | parameter counts, §3 |
| H9 | **Declared state budget `Ŝ`** — an order-of-magnitude estimate of the family's latent state count, declared once per family | BIRM (declared at instantiation) | The true state count is exactly what is latent; nothing can size an organ from a quantity it is trying to discover. `D_o` and `k` are encoding widths and do not track problem scale — a 4-action maze and a 4-action puzzle share `k` and differ by orders of magnitude | one order-of-magnitude figure per family; every organ dimension in §3 is a function of it (`D85`) |
| H10 | **Authorship *and granularity* of the action vocabulary** — which repertoire the `k` codes stand for, and at which grain. Two independent choices: whether the primitives are invented by the adapter or supplied by the environment, and — supplied or not — whether a parameterised primitive is passed as one code or enumerated into many (`D131`) | adapter | Choosing the primitives is choosing the edge set, and `H3`'s conservation law applies unchanged with edges in place of nodes: coarse primitives swallow the search into single moves, fine primitives multiply it without adding information, and the choice does **not** converge as the vocabulary is refined. Nothing in the wiki constructs a representation (`G73`) or chooses a parse (`G75`), and neither does this spec | `?` — **unquantified; blocking for interpreting §10 on any adapter-authored family, not for building**; §12 `O42`. **Never zero** (`D131`): `[[wiki/entities/arc-agi-3.md]]` supplies its primitives, but `ACTION6(x, y)` is 1 code or 4096 depending on the adapter, so its charge is small-but-nonzero; **large and unmeasured** for any format re-encoded under `D126`/`D130`. `D128`, `D131` |
| H8 | **The assumption that the family's actions compose at all** — distinct from `H6`, which is *which* group they compose in | BIRM | No test decides whether an observed action set has closure (`G41`); the precondition is a property of the domain and is checked by nobody. §7's first row makes it an *operational* test rather than a structural one, but the assumption is still made before the first step | 1 bit per family, declared; §7 `D78` |

**No content priors are installed** (`D80`). The wiki's enumerated candidate set — objects, agents, number, geometry, forms, social beings — is *structure*, not encoding, so none of it may be pushed into the adapter: an entry-gated prior sits above perceptual representations and constrains which edges may exist, which is exactly BIRM's job and not A0's. BIRM declines the whole inventory: in an arbitrary world any world-specific commitment is a bet that can be wrong, and a wrong prior is worse than no prior (`T211`). `H6` and `H8` are then BIRM's *only* installed structural bets, and they are installed in the one pattern the biology supports — **format installed, resolution learned** (the number system's ratio limit tightens 2.0 → 1.15–1.3 while the ratio-limited form never changes). The price is stated openly: a bet has no withdrawal mechanism here, and nothing in the wiki supplies one.

**Organ sizes are functions, not constants** (`D85`). No dimension in §3 is a fixed number: with `K` the per-module code size, the structural module count is `n_mod = ⌈log_K Ŝ⌉`, the store's carrier is `N_S = c·n_mod` (linear in module count, by `D17`'s capacity result, while addressable states go as `∏ᵢ Kᵢ ≈ Ŝ`), and the codec-adjacent widths `f_g` and the action head follow `k`, the observation-side encoder follows `D_o`. A benchmark is therefore plugged in by declaring `⟨D_o, k, Ŝ⟩` and re-instantiating, not by re-tuning. The two free scalars left are `K` and `c`; `Ŝ` is the only *new* prior, and it is charged as `H9`. This closes §12 `O12` and opens `O32` (how `Ŝ` is estimated for an unfamiliar family).

**What §2.2 is *not* claiming.** Every row above is a prior in the sense of `P` in the efficiency ratio. `H3` in particular means BIRM is **not** being scored on latent-graph discovery end-to-end: it is scored on discovery over a vertex set the adapter fixed. Any §10 result must be quoted with that qualification attached. `D14`

### 3.1 M — Model (slow store)

| Slot | Fill |
|---|---|
| State held | Slow weights `W`: the code vocabulary (context codes, event codes, action codes) **and** the associative weights among them, as two separately addressable parameter blocks |
| Parameter count | **Derived, not tuned** (`D85`): `n_mod = ⌈log_K Ŝ⌉` structural modules of width `K`; the content half follows `D_o`; `f_g` emits `k` operators of size `K×K`. `K` and the content-half width are the only free scalars. §12 `O12` closed |
| **Architecturally denied** | (i) Online writes — `M` is written **only** on the transport channel, so an environment step can never move a slow weight. (ii) The observation bus into the `g` half (§6 `D15`). (iii) Any ability to schedule its own transport: the filter and the stopping rule live outside it (§5.3 `D57`, `D58`) |
| Load-bearing commitment | **`S` and `M` are two organs, not one model with two learning rates** (`D22`), and what transports between them is the **mapping, not the terms** (`D23`) — `M` already holds the vocabulary at acquisition |
| Prediction space | **Representation, never input.** A pixel/observation reconstruction loss is a *weighting* over what the latent keeps, and the weighting is set by area rather than by task relevance — the object-vanishing failure. Measured at fixed protocol: a representation-space video predictor scores 98/66/62 on violation-of-expectation where a pixel-space predictor with the same predictive form sits **at the untrained null**; latent targets beat pixel targets by 26.2 points with everything else held fixed. `D86` |
| Transition regime | **Hybrid, and the hybrid's two channels are already BIRM's two codes.** The RSSM compromise (deterministic carrier + stochastic content) is not adopted as a compromise: path-invariance *requires* `g` to be deterministic, and a deterministic content channel returns the conditional mean of a plural world — which is neither outcome and merges distinct things (segmentation Average Recall 0.327 → 0.541, mIoU 0.481 → 0.681, on identical probing logic, when the same model is read generatively instead). So determinism is **required** on the structural half and **forbidden** on the content half. `D88` |
| Planner exploitation | The standing hazard of the deterministic cell: a search over a differentiable learned map is an adversary against its own model, and §5.2's rollout is such a search. The defence is the stochastic content channel (`D88`), not a better model — noise makes exploitable ridges disappear under expectation. BIRM's second, cheaper defence is `D53`'s commit failure: a candidate whose support comes from model error does not recruit a coalition and never publishes |
| What identifies it, and what does not | Two margins, both properties of the **data-generating distribution**, neither of the learner. `γ_rep` — the weakest first-order predictable direction against the strongest nonlinear alternative — belongs to the environment and cannot be raised by more data of the same kind; encoder error enters the bound **divided** by it while predictor error enters additively. `ρ_tr = λ_min(E_g[Cov(a\|g)])` — conditional action excitation — belongs to the **collector** and is a design choice; counterfactual error is `δ/ρ_tr`, and at `ρ_tr = 0` the data constrain only the closed-loop map, so `A` and `B` are not separately identifiable while on-policy loss looks fine. Both are computable before training and both are logged in §9. `D90` |
| **Architecturally denied** | (iv) **Being trained on its own converged policy's data.** Every mechanism for improving an actor drives `ρ_tr → 0`, and on-policy prediction error — the only number anyone reports — falls throughout. BIRM therefore has no behaviour-cloning stage and no plan→policy distillation (`D92`), and `N` holds an excitation floor (`D91`) |
| Known hazard | Transport past a finite point *raises* generalization error, and for a relation `M` cannot model the optimal transport is **zero** — so a scheduler that always consolidates is wrong by construction (`D24`) |
| Known hazard | **A read-out can be destroyed while nothing collapses and the loss falls monotonically.** In the one long run where both were measured, the aggregate probe rose for 1M iterations while a *patch-level* probe peaked at ~200k and ended below its own early value. Training horizon is therefore a design variable with a coefficient in nobody's objective, and §9's P1 exit criterion is a read-out peak rather than loss convergence (`D94`, §12 `O36`) |

### 3.2 S — Store (fast, instance)

| Slot | Fill |
|---|---|
| State held | Content slots; a **pointer register** typed differently from the contents (`D32`); per-slot occupancy; per-feature within-slot variance (`D74`) |
| Access protocol | `write(addr=g, content)` · `read(addr, lead_time)` · `replace` · `suppress` · `clear`. **Five primitives, not two** (`D32`) |
| **Query choice** | The address is the integrated position code `g_t` — a **position, not a want**. No goal encoding enters the read (§2.1(b)), no proposer enumerates alternative addresses, and no scorer ranks them; the monitor is `D69`'s read-confidence scalar, with step 9b firing only above threshold. The read's **only choosable variable is the lead time** (`O11`). `D132` |
| What a write contains | The **conjunction** `(Δ = m⁺ − m⁻, a_{t−1}, r_t)`, not the content delta alone — the binder must sit where cue, action and outcome converge, and an efference copy is a requirement rather than a convenience (`D76`) |
| Attractor regime | **Prestructured scaffold, discrete** (Axis 1 / Axis 2): fixed points set by the frozen random `g→S` projection, content attached, basins convex and spurious-free, capacity set by the address space, overload degrading **resolution, not identity**. Content-defined (Hopfield) and *learnable*-scaffold variants are denied (`D68`) |
| Read confidence | A **per-read confidence scalar** is emitted alongside the retrieved content, because relaxation supplies no certificate: a correct completion and a confident wrong one are the same state. Two-threshold novelty read; the scalar is a `N` input and a §10 quantity (`D69`) |
| Allocation prior | **Not a hyperparameter.** The allocate-vs-reuse knob is the *fan-out density* of the frozen `g→S` projection — the same object `D18` froze for anti-collapse reasons — so `G38`'s separation/completion bias is readable off a weight matrix rather than tuned (`D73`) |
| Read tolerance | Per feature, set by that slot's **within-slot variance**, not by similarity: a feature that has historically varied inside a context must not trigger a new allocation (`D74`) |
| Size | `N_S = c·n_mod`, linear in `M`'s structural module count and therefore logarithmic in `Ŝ` — the scaffold's whole point (`D17`, `D85`). Enlarging `Ŝ` by an order of magnitude costs a constant number of slots, not an order of magnitude of them |

### 3.3 C — Controller

**Mechanism.** `C` does not route, gate or rewire anything downstream. It holds a task model as sustained state and adds an excitatory bias to organs that are already running a competition; the competition converts a small bias into a decision, so "enhance the relevant" and "suppress the irrelevant" are one operation and there is **no dedicated suppression channel** (`D25`, `D26`).

| Slot | Fill |
|---|---|
| State held | The task model (sustained, swappable, broadcast); `k` per-level engagement gains; the pointer/schedule registers it drives into `S` |
| Factorization | Three axes, orthogonal and composed: **by operation** — one common component + `θ_upd` + `θ_shift`, **no inhibition-specific parameters** (`D27`); **by output port** — typed channels whose meaning is fixed by their reader (`D28`); **by policy order** — `k` level-searchers, all live from step 1 (`D29`) |

### 3.6 What §3 does not have

- **No competence estimator.** The biological default self-model is signed-inflated and its calibrator is a separate, lesionable module with an external referent — so adding a self-assessor to `C` would install the failure mode along with the function. §12 `O14`.
- **No detector organ.** Conflict, difficulty, error and novelty are all refused as engagement variables (`D30`); nothing in BIRM computes them.
- **No transfer path out of `C`.** No operation moves a representation from the control layer into a store that runs it without the controller — `C` biases a competition it does not compute (`D25`), so there is nothing in it to move. Automaticity is `D30`'s disengagement, and the claim is unmeasured: §12 `O47`. `D140`
- **No operator-borrowing path.** No organ's update rule may be called on an argument of another organ's type: `D45`'s separate content and context wires *are* the type check, and `Bg` is denied to every reader outside the address/context set (§4). §7's rebinding reuses `M`'s operator on a new index→primitive map, which is the same type. §12 `O45`. `D137`

### 4.1 Interface state per edge

Each edge carries four separable registers, and they are separately manipulable:

| Register | Set by | Timescale | Why it is not foldable into the weight |
|---|---|---|---|
| **weight** | the edge's own learning rule | slow | — |
| **terminal gain** | `U` via the receiver's decoder | seconds-reversible, content-free | A gain register lets a system trade stability margin for capacity without touching what is stored (`G56`) |
| **writability** | a *third* organ, never the two endpoints (`G53`) | event | The licensor is the network's own third node; no node is privileged as gate-setter |
| **operating point** | `N`, per component | slow | Every component has an optimum, not a monotone gain (§3.5 `D37`) |

**Edge classes.** `Bx` edges are direct, time-locked, tuned and causally dominant. `Bg` edges are relayed, low-passed, untuned, high-rate and causally weak on content — **and the relay owns the destination table**, so one organ's context can be delivered to an organ its content does not reach. Two consequences accepted here: an activity-magnitude estimate of "which edge matters" inverts the two classes (the high-rate edge is the causally irrelevant one), so §10 may not infer connectivity from co-activity; and "one global temperature vs. `N` independent ones" is a false choice — the middle option (a small state vector with a routing table over organ pairs) is what `D40` installs.

| Scoring | Rollouts are scored against **prior expectations over observation trajectories**, not against a value function that must be solved for. This deletes the Bellman solve and relocates the difficulty into where the priors come from — which is `O6`/§8, not here |
| **What is scored is a policy, not a plan** | A fixed action sequence systematically **undervalues an action whose worth is what it enables**: if `a₁` leads to either of two successors each needing a different follow-up, both continuations score badly in isolation and `a₁` inherits their cost. The repair is to score `q(a_t \| g_{t−1})` — the action marginalised out of the joint over rollout states — so `a₁` is priced against the responses BIRM *would make* at each successor. This costs BIRM nothing, because `C` is already in the loop at **every** rollout step (row 6) rather than only at the end. Measured price of getting it wrong: a plan-based scorer visits the informative cue in 66% of episodes against 100%. `D99` |
| Where the epistemic term enters | Inside the selector, at row 6, **added late and separately gated**. The pragmatic term is computed first and the epistemic term arrives as a `U`-gated addition `N` can zero — which is the one shape that makes the known failure recoverable: every neural agent that computes one joint `G` in a single head is beaten by its own reward-only ablation, and the epistemic term's characteristic failure is *dominating into policy collapse*. Sequential assembly with pragmatic-first is also what the one human recording of the two terms reports. `D95`, `D98` |
| Known hazard | The commit **free-runs** (`D62`): rollouts can start with no request. Rumination is the always-on setting of `g_rel`, and the implementation must be able to exhibit it or the gain is not real (§3.4) |

| **Sampling filter** | **Uniform-coverage admission + recall-gated write.** Both halves are refusals of the machine standard: reward-proportional sampling is indistinguishable from uniform, and uncertainty-proportional sampling is *worse than not doing continual learning at all* — the two criteria machines actually use are the two that fail. `D57` |

| Composition operator | Accept the composed pair with probability rising in the terminal state's value, and update the **earlier** item from the later one. | Schedule | **Two stages.** A cheap scalar tag is written online at encoding, from recency and outcome, and **never refreshed**; the offline distribution is drawn from the tags. Priority is deliberately stale — that is what frees the online phase. `D60` `(tentative)` |
| Why the uncertainty refusal is not a coincidence | The same uncertainty quantity is a **good thing to act on and a bad thing to rehearse on**, measured on one architecture: as an action bonus it raises 8-task continual performance 0.09 → 0.28 and cuts forgetting 0.37 → 0.13; used to prioritise which stored episodes the model trains on, it performs at the level of the *non-continual* baseline, worse than uniform on every metric. The mechanism is that an exploration bonus is **consumed** the moment it is acted on while a replay priority is **persistent**, so the buffer keeps re-presenting whatever the model cannot predict — disproportionately noise it will never predict. §8's epistemic term and §5.3's sampler therefore read the same statistic and must not share a weight. `D105` |
| What this does **not** buy | Recall gating is a **reliability filter, not a causality filter**: a shortcut that recurs stably passes it exactly as easily as structure does. Nothing in §5.3 separates a shortcut from a cause, and reading it as if it did would be the error |

### 5.4 Mode arbitration

| Slot | Fill |
|---|---|
| Quantity the arbitrator compares | Aggregate activity arriving on `Bx⁺` against the commit threshold — **not** a residual against the input. The trigger is a change in the *attended content*, not a change in the input; the two coincide when something new arrives and separate when the incumbent merely loses support. So BIRM emits **one boundary per event and none at offset**. `D54` |
| Where it is computed | `X`, as the **bifurcation point of the settling cascade** — not a comparator constant. Sensitivity is the fidelity of propagation into `X`; bias is the *pre-commit resting distance* from threshold, set by `U`. Both are readable before the input arrives, which makes the idle-state gain a legitimate place to spend control effort. `D53` |
| Hysteresis / commit discipline | Occupancy is **exclusive** and held by recurrence for a dwell time. **Release is a content-free event, scheduled separately from which-content** — it dissolves the hold and the next occupant moves in, rather than winning the bus outright (measured: the release event leads the content change by ~209 ms in 86–89% of transitions). Commit and content-selection are therefore two schedulable things, and BIRM keeps them apart. `D56` |
| Sub-threshold case | A **failed commit** must be an expressible state: partial recruitment, logged, distinct from both a completed commit and a blend. In the biology it is 51% site recruitment against 100%, at a burst rate of 0.147 vs 0.17 with a 0.015 floor. A continuous mixture cannot produce it, which is why it is the cheapest test that the gate is real. `D53` |
| In-flight rollouts on a switch | **Not discarded.** An un-committed candidate decays but stays *promotable* for a bounded window, so a later signal can publish it — the deferred-commit rule (biological window: ~900 ms). A switch stops feeding the pool; it does not flush it. `D55` |
| Commit vs. update | **The commit is exclusive; the update is not.** Publication on `W` stays winner-take-all (`D53`, `D56`); *memory updating* is responsibility-weighted across every stored structure, `Δ_j ∝ λ_j · k_j · e_j`. These are not in conflict — one is a bus occupancy, the other a plasticity gate — and the argmax alternative has a measured price: a new context whose policy partially matches two stored ones is learned **more slowly** than one matching neither, visible as an excess of exactly one error type. `D75` |
| Alternation between stored structures | **A recency term on the commit gate, not a sample from a posterior.** Occupancy is exclusive (`D53`, `D56`) and an abandoned candidate stays promotable while it decays (`D55`), so repeated switching is what a decaying per-slot bias plus a periodic threshold test produces. BIRM maintains no distribution over which structure is currently active, and §10 may not read alternation as evidence that one is represented. `D144` |
| What is graded, by operation | **Allocate: argmax. Express: exclusive. Update: graded.** Allocation is read off the fan-out density of the frozen `g→S` projection (`D73`), publication on `W` is winner-take-all (`D75`), and plasticity is responsibility-weighted across every stored structure (`D75`) — hard where the decision is discrete and irreversible, soft where it is continuous and recoverable. The remaining route, a mixture carried as *code overlap* trained to match situation similarity, is architecturally unavailable: `D18`'s frozen random projection has no similarity structure to overlap. `D141` |
| Failure mode inherited, stated openly | The system **hallucinates by the mechanism it perceives by**: a spontaneous supra-threshold cascade is indistinguishable downstream from a driven one, and in the biology a false alarm is reported exactly like a hit. The only available fix is at the propagation stage, not at the gate |

## 6. The factorization — where `g`/`x` is installed and what makes it pay rent

> The wiki's central negative result: no objective is known that prefers a factorized code, and a constant code satisfies path-consistency trivially. So this section is architecture, not loss — and it needs an anti-collapse provision *before* any of it is scored.

| Slot | Fill |
|---|---|
| Mechanism that generates `g` | **Action-accumulated path integration with a per-action operator**: `g_t = ℓ₂(W_{a_t} g_{t−1})`, `W_a = f_g(a)` produced by one small generator from the action index, so an operator is *computed* rather than stored per action. `g` never reads `o_t`; content enters only through the conjunction `p = f(g, x)`. `D15` amended by `D65`; operator form `D63` |
| What makes `g` path-consistent by construction (if anything) | **Path-invariance, not commutativity.** The requirement is that every route *reaching a given state* produce the same `g` — a monoid, not a group: `uncle = father ∘ brother ≠ brother ∘ father` must remain expressible, which matrix composition of `W_a` gives and phase addition does not. The abelian "equal total displacement" reading is the special case and is **withdrawn** (`D63` supersedes `D16`). Still **conditional** on the family's actions composing (`G41`, `H8`); §7's first row decides it operationally, and if it fails this section is void and falls back to §12 `O4` |
| The two constraints that generate the code | *Distinctness* and *path-invariance*, both consequences of `g` being a **memory address** and of nothing spatial. Claimed sufficient to produce grid and band codes with no spatial target in the loss — which is why §6 stays architecture rather than objective |
| How `g`'s drift is corrected — **and it is not by the observation** | The observation bus stays denied. Correction arrives on a **new edge, `S → Bg`**: the content-addressed read of `S` returns previously-written places carrying a similar observation, and the returned code is folded into `g_t` as a **discrete, offset-preserving reset** — measured in a fully imaged integrator, where a displaced landmark makes the code *jump while preserving its offset* and cue-conflict is won outright by the cue rather than averaged. Anchoring is therefore implemented as recall, with no landmark machinery and no reset module. Cost accepted: the reset has its own time constant that no model supplies (`O27`), and the anchor is a **recalled place** — neither a landmark nor the self-motion stream (`D143`). `D65` supersedes `D15` |
| What makes a content-contaminated `g` **cost the agent task reward** (rent) | `g` is the **address of the fast store `S`** and is used for nothing else. Two requirements then become forced rather than stipulated: *distinctness* (different states must get different codes or their memories collide) and *path-invariance* (the same state must code the same from any direction or the memory is unretrievable); content-invariance follows, because an address must not depend on what is stored at it. Contamination therefore shows up as **retrieval failure**, which is paid in task reward on the same step. Capacity is the second rent: a frozen random projection from `M` structural modules into `S` makes all `∏ᵢ Kᵢ` states stable attractors with `N_S` growing only **linearly in `M`** — and content-shuffled scaffolds with *learned* bidirectional weights lose the exponential scaling entirely. `D17` |
| Anti-collapse provision, and whether it is a design-time property or a runtime monitor | **Both, and the design-time half comes first.** Design-time: `g` is *architecturally denied* the observation bus, so the constant-encoder solution is not reachable by contaminating it with content — and the `g→S` projection is **fixed and random** with a pointwise nonlinearity (a linear layer fails), so there is no weight that can collapse it. Runtime: **CCGP and parallelism score** over an enumerable condition grid, logged per evaluation round — **not decoding accuracy**, which in the one dataset reporting both was statistically unchanged while CCGP rose. `D18` |
| Path-**invariance** residual: formula, when logged | `ρ = ‖g_int − g_rec‖₂ / ‖g_int‖₂` — the integrated code against the code returned by the content-certified recall of step 9b. The content channel is the only available certificate: under non-abelian `W_a` "equal total displacement" is undefined, and node identity is latent. Logged on every above-threshold recall, reported as a distribution, never a mean. `D64` |
| The circularity this buys, stated | `ρ` audits the structural code using the content channel, so a content channel that is itself wrong produces a clean `ρ`. This is not removable within the spec; it is `O28`, and it caps what a §10 row built on `ρ` can claim |
| Attractor regimes, named | `g` is a **continuous** attractor (translation-invariant recurrence; the manifold is `H6`); `S` is the **prestructured-scaffold discrete** regime. Denied: a content-defined (Hopfield) `S`, whose overload is catastrophic rather than graceful; and a *learnable* scaffold — the one case that unfroze it got worse (`FID_p` 43.41 → 47.76), because the codes stand in dynamical relations a per-code gradient does not respect. `D68` |
| What sets the code's **scale**, and why BIRM currently has exactly one | The interval between `S` writes. Between writes the integrator must predict that many steps ahead unaided, and the emergent period scales monotonically with the interval. §5.1 writes every step, so BIRM has a **single fine-scale code and no multi-module code** — the same hole every trained system in the wiki has. Several scales require `n_mod` integrators at distinct write intervals, and the effect is **training-time only**: changing the interval at test time leaves the scale untouched. Correlational payoff: grid score predicts 512-step imagination accuracy (`ρ = 0.783, p = 1e-6`), with counterexamples at low grid score and high accuracy, so periodicity is sufficient and demonstrably not necessary. `D66`, `O24` |
| When a periodic `g` is worth having at all | At **intermediate observation ambiguity**. Grid coding peaks there and *collapses* when observations uniquely identify the state — the code is a compensation for aliasing, not a general consequence of integrating actions. This is **not** a coupling to be swept but the scope test of `D84`: `H1`'s informativeness decides whether the family is in scope at all, and an encoding that resolves the state uniquely has moved the family out of §1 rather than broken §6. *Wave 6a:* `D126` reduces §1's exclusions to this one, so this row now carries the **entire** scope test — and it is a test on the *adapter*, not on the benchmark: a family whose adapter fully rewrites the observation each step has excluded itself regardless of which benchmark it came from. `D67`, `D84`, `D126` |
| Manifold topology: assumed or learned; if assumed, stated here as a designer decision | **Assumed — a designer decision, recorded as `H6`.** Which group the displacements act in is chosen per family and not inferred. Two consequences accepted openly: the code cannot compose a joint space from marginals never sampled together, and a family whose true structure is not of the assumed type will be forced onto it silently. `D20` |
| Node set / discretisation: what supplies it | **The adapter, as `H3`** — for the *stream*. Stated here rather than hidden: this is the part of latent-graph discovery the spec does not attempt, and the conservation law means the amount conceded is unmeasured. `D21` |
| What BIRM discretises *on top of* the adapter | **Effect-equivalence.** A binary bottleneck inside an effect predictor — `b = round(σ(f_enc(o)))`, `ê = g_dec(b, a_{t−1})`, `L = ‖ê − (o_t − o_{t−1})‖²` — so `b(x₁) = b(x₂) ⟺ ∀a ∈ A: effect(x₁,a) ≈ effect(x₂,a)`. `Bx`'s content code is then typed **by consequence, not by appearance**, and each code arrives with its own applicability mask (`⟨precondition, action, effect⟩` is a typed edge). This is the only carving criterion in the wiki whose supervision comes from outside the observation stream, and BIRM can compute it because it has a repertoire. `D71` |
| What that does *not* fix | The classes are **repertoire-limited**: two things the action set cannot separate never get two codes, however different they look, and no system reports the shortfall (`O25`). It also does not remove `H3` — it puts a second discretisation *inside* BIRM, so the residual is the composition of the adapter's carve and BIRM's own |
| Anti-collapse monitor #2, and why it is needed | The **split-recombine test**: factorize iff the effect predictor's loss is unchanged when `b` is split and the parts recombined. It needs no enumerable condition grid, so it survives exactly where CCGP/PS cannot be computed — which `O9` flags as likely on the primary benchmark. `D72` |
| Free structural instrument (no data) | Attractor–eigenvector alignment and convergence time against a **degree-preserving permutation of the same weights**: computable from `S`'s weight matrix alone. The wiki's only probe that is not label-dependent, and therefore the only §10 candidate that cannot be gamed by the evaluation family. `D82` |

**The allocate-vs-reuse prior is the `g→S` projection's fan-out density** — the same projection `D18` froze. Sweeping a context→store projection from fully random toward one-to-one moves the fitted Dirichlet `α` at `r = 0.76, p < 2×10⁻⁴` and moves nothing else. So `G38`'s separation/completion bias is not a hyperparameter BIRM has to tune; it is a fan-out statistic readable off a frozen weight matrix (`D73`).

**What §6 does not have** (`G30`): no objective function is maximised by a path-consistent `g` and minimised by a contaminated one. Everything above is *architecture* and *rent* — the code is built and made to pay, never **trained toward**. The nearest shapes in the wiki are a relations-only Gram penalty (label-free, but no path term and within-input only) and long-range predictability (rewards content-invariance, says nothing about commutativity). Recorded as §12 `O5`.

**`O5` stays open, and the collapse literature is not what closes it.** It supplies no objective preferring a path-consistent `g`; what it supplies is a **derived target for the anti-collapse half** — at fixed total variance, anisotropy raises both the bias and the variance of a linear probe, and among distributions under a scalar covariance constraint the **isotropic Gaussian uniquely minimises** the integrated squared bias of nearest-neighbour and kernel probes. BIRM installs the isotropic-Gaussian marginal on the content encoder (`D87`). It is silent about paths. Three narrowings come with it:

| Narrowing | Consequence for §6 |
|---|---|
| Certifiable in the **target**, not the trajectory | A loss whose minimum is provably non-collapsed still collapses over most of its coefficient space. Stating `D18`'s minimum certifies nothing about the run |
| Certifiable **per read-out**, not globally | Two probes on one encoder moved in opposite directions across 1M iterations of a run in which no term diverged. `D18`'s CCGP/PS monitor must therefore be joined by a probe on whatever read-out §10 will actually use, and both plotted against training time (`D94`) |
| Possibly not certifiable from the loss at all | A supervised objective with **no degenerate minimum** collapses anyway (20.73% top-1, recovering to 72.02% with an isotropy term added), on the reading that the driving term is the optimiser's flux rather than the loss's shape. Every provision is then a **drift control** first |

| **No discardable head exists** | The space BIRM constrains and the space its readers read are one space — §4 defines a space by who may read it, and no projector stands between the `x` encoder and `M`, `S` or `C`. The literature's cheapest provision, *hosting* a degenerate solution in a head thrown away at read-out, therefore has no site here; `D87`'s isotropy term is paid on the read space itself. §12 `O46`. `D139` |

**The frozen random `g→S` projection is kept and the multiplicative conjunction `p = g̃ ⊙ x̃` is declined** (`D17`, `D18`). The frozen projection buys exponentially many convex attractors with `N_S` linear in the module count; learning those weights destroys the exponential scaling. The conjunction costs `×n_c` units per additional bound region, its transformer rewrite predicts *random* remapping, and a spiking rewrite recovers the grid code only after the conjunction is **deleted**.

## 7. Action-vocabulary rebinding

> The same action code must be able to mean something different in a new environment. Where no relation exists between cue and consequence, no mechanism can be cheaper than one-pair-at-a-time binding — so the design question is *binding speed and where the binding is stored*, not a clever transform.

| Slot | Fill |
|---|---|
| Test that decides whether this domain's actions compose | **Operational, not structural** — no structural test exists (`G41`, and the wiki's own counterexample, a bare social network, has no diagnostic). BIRM runs the two addressing schemes on the same stream and compares **retrieval**: the path-integrated address `g` against a per-observation clone-pool address fitted by expectation–maximisation. Actions compose for this family iff the integrated address wins on re-visit retrieval and on transfer to a held-out instance-graph; if the clones win, §6 is void for that family. The test is therefore a §9 pipeline stage, not a pre-flight check, and it costs one extra store. `D78` |
| Path if they compose | §6 as written: one `g`, `k` operators `W_a = f_g(a)`, `S` addressed by `g`, transfer free because all positions are treated alike (a new node needs no new cell and no new synapses, and re-alignment to a same-shaped environment is not a graph-matching problem) |
| Path if they do not | The clone pool becomes the address: de-alias fast, locally, per environment, transferring nothing (`O4`). The merge of the two is named in the wiki as an obvious unbuilt model. BIRM's fallback is the clone pool **plus** the unchanged `S` protocol — the store does not care where its address came from, which is the one thing `D17` buys here |
| Where a rebinding is written | **In `S`, as an edge, and never in weights.** The represented object is the *pairing*: ~50% of prefrontal cells code the cue×action conjunction against ~30% cue and ~20% action, with reversal (marginals fixed, edge set flipped) as the control, and the tuning is **nonlinear** — activity for one pairing is not predictable from the others. Two consequences BIRM must honour: (i) the write content is the conjunction `(Δ, a_{t−1}, r_t)` (`D76`), because the binder cannot form cue×action×outcome from the sensory stream alone and needs the efference copy; (ii) a binding module fed only by the observation encoder cannot learn what it is for, which is how most memory-augmented architectures in the wiki are wired |
| What is rebound, and what is not | Rebound: the **action→operator generator** `f_g : a ↦ W_a`, `k` operators, plus the `S` edges written under it. Preserved **across environments**: `g`'s integrator dynamics, the `g→S` projection, `M`'s associative weights, the effect-equivalence codebook. So a rebinding is a re-fit of one small generator, not of the model. `D77`, amended by `D102` |
| What is *not* preserved across **bodies** | The **effect-equivalence codebook**. `D71` defines a class by `∀a ∈ A: effect(x₁,a) ≈ effect(x₂,a)`, quantified over *this* repertoire, so a change of body changes the quantifier and the codebook dies with it. Wave 4 listed it as preserved without distinguishing the two cases; `D102` supersedes `D77` on that cell. The field's own practice agrees in shape and disagrees in emphasis — one interface is routinely fitted above 22 robot types, and in **every** such family a body-specific decoder is still there underneath, so the repertoire-relative part is *relocated, never removed* (`T172`). What survives a body change in BIRM is `g`, `M`'s associative weights and the `S` protocol; what dies is `f_g`, the codebook, and the adapter |
| **Size** of the per-body part — `O29` closed | It is not an unreported number after all, because BIRM already derived it: the per-body part is `f_g` plus the adapter, and `D85` makes `f_g` a generator emitting `k` operators of size `K×K`. So the decoder size is a function of `⟨k, K⟩` and nothing new is open. The literature's version of this question stays open in the literature — no source reports what its shared interface *cannot express* about any member body — but BIRM does not inherit it. `D102` |
| Second acceptance number, measured on a brain | State-machine reuse with sensory-leaf rebinding: an established latent-state machine relearned for an **unfamiliar cue pair in 147 ± 39 trials against 483 ± 70** for the original — a ~3.3× speedup — with population correlation between old-cue and new-cue trials high **everywhere except the cue region**. That is `D77`'s claim (rebind the leaf, keep the machine) measured, and it is the number §10 scores structure reuse against, distinct from `D79`'s ≤8 trials/cue for arbitrary bindings, which measures binding speed on a *new* leaf rather than reuse of an old machine. `D103` |
| Budget | **≤ 8 trials/cue to <10% error at `k = 3`**; ~3 trials/cue to substantial learning; 24 new mappings/day sustained in an experienced learner. `MEASURED` on the biology and adopted as the acceptance number — no gradient step is available at that timescale, which is why the write is one-shot and lives in `S` |
| What licenses a particular binding | **Unsolved, and BIRM inherits it.** Nothing says how the network decides that *this* cue binds to *that* action rather than to the other pairings available in the trial; reinforcement is the only stated selector and is too slow and too coarse for 3 trials/cue. BIRM's cheapest candidate is the responsibility posterior — one quantity controlling creation, expression and updating at once (`D75`) — with the context supplying what no structural relation can. `O30` |
| The strategy floor, and why it is not installed | Repeat-Stay/Change-Shift is a **separately stored object** (it survives fast-store ablation while new bindings fail, and dies with the rule store while the bindings' substrate is untouched) and is worth exactly `E = ⅓·0 + ⅔·0.5 = 33%` error at `k = 3`. BIRM installs none of it: §1's control task exists precisely to detect it, and at `k = 2` it is a *complete* solution, which is why S5 forbids two-alternative scoring. `D79` |
| What an abstraction layer buys here | **A rate multiplier, not an enabler.** Higher-order rules are not necessary to acquire the exemplars — they change the constant in front of `O(n)` by pruning which input dimensions are candidates, and cannot change the exponent, because arbitrary edges have no shared content to factor out. `D29`'s `k` parallel level-searchers must therefore not be expected to buy a sample-complexity *class*; expecting that is expecting something the biology does not deliver |
| Curriculum knob (the one lever that moves which mechanism runs) | **Cue–choice contiguity.** Tasks that *could* be solved by arbitrary binding are instead solved by approach-by-valence when cue and choice are contiguous in time and space; separating them is what recruits the binding path. A benchmark that leaves contiguity uncontrolled does not know which mechanism it is scoring — which is a constraint on §1's secondary family, not a free parameter |
| What is preserved across *bodies* (the body-independent level) | `g`, `M` and the `S` protocol; the per-body part is `f_g` plus the adapter. Consistent with the practice of fitting one action interface above many embodiments while keeping a small per-body decoder underneath — the repertoire-relative part is relocated, never removed (`T172`). The **size** of that decoder is **derived, not open**: `f_g` emits `k` operators of size `K×K` (`D85`), so it is a function of `⟨k, K⟩`. §12 `O29` closed by `D102`, which also corrects this row — the effect-equivalence codebook was listed as body-independent and is not |
| Engagement signal, re-confirmed | The acquisition network is driven *harder* by a set with a hidden rule than by a matched ruleless set that is **harder, more uncertain and generates more error feedback** — so engagement is neither error, novelty, uncertainty nor effort. This is an independent confirmation of `D30`'s four refusals, and the discriminating machine run is the same design: train on a structured task and a matched scrambled one, and require an internal quantity to separate them *opposite* to loss |

**What §7 does not have.** No mechanism converts a set of specific bindings into the rule over them, and the extraction cannot be driven by failure to acquire the exemplars, since the rule is not needed to acquire them — so the abstraction layer has **no named error signal** in this section or anywhere in the wiki. Recorded as `O31`.

## 8. Exploration vs. exploitation

> Requirement: derived from a quantity the agent already computes, and evaluated *inside* the selector — not an external schedule, not a decayed epsilon.

> **Four incompatible quantities circulate under the name "epistemic value", and picking the wrong one is not a tuning error — it is a different agent.** §8's first job is to choose a row.

| # | Quantity | Over what distribution | Pays for | Status in BIRM |

| Why a discount could not have moved the trade-off anyway | Unrolling that recursion puts **every** term at depth `k` — cost `c_k`, information gain `I_k`, and the commit reward — at weight `γ^k`. A discount is a *uniform weighting over depth*, not a differential weighting between the epistemic and pragmatic terms, so it cannot change their ratio at any fixed depth. The source's own summary agrees and points the other way: `I_k(b)` enters **undiscounted at the current step** while the continuation is discounted, so a lower `γ` produces *more* exploratory behaviour early, and performance is reported **robust across `γ ∈ {0.9, 0.95, 0.99, 1.0}`**. The apparent asymmetry comes entirely from *where the two payoffs sit on the depth axis* — information now, reward at the commit — which is the same observation the hyperbolic-kernel literature makes about the same axis. `D108` |
| What the measured reversal actually measures, and the requirement it forces | **Depth, in probes.** The advantage falls only on **multi-observation** environments and the mechanism is that discounting truncates the effective horizon below the number of probes that must be *chained* before a confident commit; on the single-observation environment the same agent is insensitive to `γ` across the whole range `[0.90, 1.0]`. Independently: at planning horizon `H = 1` the term degenerates to myopic information gain no matter what `γ` is. BIRM's requirement is therefore stated in the units the effect is actually in — **the rollout must be able to chain `H ≥ 2` information-gathering commits before a pragmatic one** — and not as a floor on any discount. `D108` |
| Where that requirement is charged | Not to `N`. BIRM's rollout depth is set by **commit failure** (`D53`, `D62`), so the quantity that decides whether two probes can be chained is the commit gate's *pre-commit resting distance from threshold* — which is `O18`'s stability budget, the knob already known to set take-off, decision speed and the admission threshold together. "How deep can BIRM plan" and "how easily does it commit" are **one knob**, and §8's depth requirement is a second claim on it. `D109` |
| The leak test | The two `γ`s are only separate if nothing wires them together, and the discriminating run is the one the source already published in reverse: on a family where **one** probe suffices, BIRM's score must be **insensitive** to `γ` across `[0.90, 1.0]`; on a family needing `n` chained probes, its score must fall exactly when achievable rollout depth drops below `n` — and not before. Sensitivity on the single-probe family means the estimation discount has leaked into the rollout scorer and `D107` is not implemented. §10 row (i). `D107` |
| What BIRM must not do with this quantity | Reuse it as a **replay priority**. Same statistic, opposite verdict: good to act on, harmful to rehearse on, because a bonus is consumed when acted on and a priority is persistent. §5.3's refusal of uncertainty-proportional sampling (`D57`) and §8's adoption of E3 are consistent only because the two never share a weight. `D105` |
| **Second factor** | `expressed competence ≈ representation × motivation`. The affect channel is **not** a term added to the return: it is a standing dispositional gate on whether a class of computation is run at all, read by `N` at second order (`D70`, closes `O6`). Two within-species manipulations carry it — the same agent succeeds or fails at one cooperation task depending only on whether the reward is dispersed or monopolisable, and social learning is abolished outright by intolerance, with the machinery held fixed in both. No architecture in the wiki has such a state (`G102`); what *sets* the disposition is `O26` |

## 9. Training pipeline

> **The pipeline has four stages and one of the template's four is deleted.** `P2 behaviour cloning` is refused outright (`D92`): distilling a planner into a reactive policy fits a *deterministic* `A(s)`, which is precisely the operation that drives `ρ_tr → 0` and makes the data the agent subsequently collects unable to identify the model it plans with — while its on-policy prediction loss falls throughout and reports nothing. The slot is re-used for a controller fit with `M` frozen.

| Stage | Data collector / policy | Objective | What is frozen | What is logged | Exit criterion | Known hazard |
|---|---|---|---|---|---|---|
| **P0 vocabulary** | **Heterogeneous random play** across the declared family. Excitation is bought from *source heterogeneity*, not from dither — a union of unrelated behaviours has high conditional action variance by construction and costs no return (`D91`) | (i) `D71`'s effect-equivalence bottleneck: `b = round(σ(f_enc(o)))`, `ê = g_dec(b, a_{t−1})`, `L = ‖ê − (o_t − o_{t−1})‖²`. | Question | Answer |
|---|---|
| Is a random-play collector kept running alongside the improving policy? | **Yes, through P1, and its floor survives into P3 as a dither term.** Not a hedge: `ρ_tr` is a property of the *collector* and not of the architecture or the loss, counterfactual error is `δ/ρ_tr`, and the only number anyone reports — on-policy prediction error — is blind to it. The one system in the wiki whose action model works at scale got its excitation for free from **human teleoperation across many operators including failures**, and nobody framed it that way. `D91`, `D92` |
| What crosses a stage boundary unchanged, and what is re-initialised? | Crosses unchanged: the codebook (P0→P1→P3), the frozen `g→S` projection, `M`'s associative weights (P1→P2→P3), `g`'s integrator dynamics. Dies with the body: `f_g`, the codebook, the adapter (`D102`) |
| Gain/learning-rate schedule at each boundary (the interface, not the module) | **There is no schedule, because there is no re-tuning.** `D85` makes every dimension a function of `⟨D_o, k, Ŝ⟩`, and `N` computes every gain and learning rate from the learner's own second-order statistics (`D42`), so a stage boundary cannot be a hyperparameter event. What a boundary *is* is a **licensing change**: which `L_part` gates are open and which organs may receive a learning signal at all. P1→P2 closes `M`'s gate; P2→P3 closes every gradient gate and leaves only the transport channel. The interface is the `L` bus, and the schedule is one row of it |
| What P1 must be trained on | An environment **family**, not an environment. Transfer is bought by gradient training across structurally similar worlds and by nothing else: the learning-to-learn curve — many visits per node early, correct on the *second* visit late, regardless of the edge taken — is the acquisition of the structure and the memory policy together, and it is the curve P1's exit criterion reads. The price is stated where it belongs, in §3.1: a genuinely novel structure is not acquirable in one traversal, which is what `O4`'s clone fallback exists for |

## 10. Acceptance tests

> One row per organ, per bus, and per claim class. A test whose failure mode is "we would notice" is not a test.

> **§10 is not an invention site.** Twenty-five certification instruments already exist, are numbered `I1`–`I25`, and **none is sufficient**; fourteen failure modes `F1`–`F14` are shared across them rather than belonging to any one. So §10's job is (i) to **select** from that menu, (ii) to **declare which failure modes each selection inherits**, and (iii) to state what the section therefore may not claim. An instrument's cost decides whether it is ever run, so the menu below is ordered cheapest-first and the cheapest rows are the ones made mandatory. `D112`
>
> **No emergence claims.** Which objective a system optimises is not recoverable from its representations, and which representation an objective yields is not recoverable from the objective. BIRM therefore makes **no emergence claims at all**: every structural property in §6 is a *decision* with a ledger row, never a property that fell out. §11 is not documentation of §10 — it is the substitute for the claims §10 is not allowed to license. `D118`

### 10.4 The reporting block — mandatory with every score

A §10 number is void without all seven fields. `D121`, `D122`

| Field | Content | Why |
|---|---|---|
| **Cost** | Compute and wall-clock per task | `S1`. And it is load-bearing here specifically: RHAE counts only environment-changing actions, so a system with unbounded per-action deliberation is maximally efficient by the metric (`G17`) |
| **§2.2 denominator** | The full hardwiring ledger, `H3` and `H9` included | `S4`. A score without its priors enumerated is uninterpretable |
| **`⟨D_o, k, Ŝ⟩`** | The instantiation triple | `D85` — every organ dimension is a function of it, so a score is a property of the triple |
| **Both margins** | `γ_rep`, `ρ_tr` | `T26` |
| **Facet vector** | Not a scalar: `(family score, control-task score, congruent/incongruent pair, exploration/execution pair, plan-alignment rate, unintended-successful share)` | An honest instrument returns a vector. Reached independently from two sides: `0.92` i.i.d. accuracy coexisting with `0.72` systematicity, `0.50` productivity, `0.54` localism; and a concept-variation score that **rises** on one concept while falling 11 points on another |
| **`n` and `1/n`** *(new)* | The item/level/environment count, and the resolution it implies. **Comparisons below `1/n` are refused** | `F11`: the field routinely quotes a 15-item instrument to a tenth of a point and compares systems 2–3 points apart on it, at ≈3.7× the standard error of a 200-item benchmark. The fix is arithmetic and nobody applies it |
| **Stock reads** *(new)* | How many times each evaluation set has been read, and by whom | `S3` plus `F1`: developer-blindness is a **depleting stock**, not a property — ~10,000 reported scores absorbed against 100 private tasks. The counter is the only thing that makes the depletion visible |
