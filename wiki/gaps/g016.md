# G16 — The intended graph is not identifiable from data alone

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** An inductive bias is stated that provably prefers the structural rule over the shortcut on a single environment, or the wiki accepts that identifiability requires a supplied environment family and the row is reclassified as a design cost rather than a gap.

## Why it blocks the target

Shortcut and causal rules are equally consistent with the observations, so no objective computed on one environment can prefer the structural rule. The `g`/`x` factorization G1 asks for therefore cannot be *discovered* — it must be imposed through inductive bias. The complete control surface is four levers (architecture, training data, loss, optimizer) and there is no account of which one buys graph-structured solutions, nor at what cost

## Best current answer

Multi-environment invariance where a family is given; cross-entropy's early-stopping-at-first-sufficient-predictor identified as the sharpest loss-side target. **First concrete architecture-lever proposal:** split the predictor into three *typed* channels — top-down (item content, generalising over space), spatial (frame-of-reference mappings between encodings), temporal (change given forces) — so an appearance-only rule is not expressible in the two structural channels. Butz 2016 argues this is *necessary*: free-energy minimisation is indifferent to which encodings develop, so structural priors must be added on top of the objective. Stipulated functionally, not derived, and never implemented **Rival count of the surface:** Richards et al. 2019 give three components (objective, learning rule, architecture) and demote training data to an *anchor* — the components are compressible because they pass through the genome, the environment is not because it is the high-entropy source. If that reading is right, the data lever cannot be part of the design and G16 must be paid for entirely from the other three ([[wiki/empirical-tensions.md]] T15)  **Loss lever, formal statement:** cross-entropy is a functional of the predictive distribution `Q` alone, so a shortcut rule and the intended rule inducing the same `Q` have *identical* loss at every point — no amount of data on one environment separates them, and the objective additionally carries an unchosen mode-covering preference that averages across one-to-many transitions ([[wiki/concepts/divergence-objectives.md]]). This closes the loss lever as a candidate answer to G16 rather than filling it. **A fifth lever the four-way count does not contain — *presentation*:** hold architecture, loss, optimizer and the data-generating rule all fixed, and change only whether the examples arrive as one corpus or as a stream of tasks whose latent parameter is resampled per episode. That alone moves systematic generalization from 0% to 100% on the same architecture ([[wiki/entities/mlc.md]]), so the intended rule *is* selectable from data when the presentation makes the latent variable vary — which is the multi-environment invariance argument realised at episode granularity, and the strongest counterweight this row has ([[wiki/empirical-tensions.md]] T200). It buys only the facets the sampler varies (G66)
