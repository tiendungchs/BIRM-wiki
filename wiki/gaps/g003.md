# G3 — Nothing enforces path-consistency of `g`

**Status:** `PARTIAL`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** Commutativity is measured directly — the same code reached by two different paths to one node — on a graph family with no consistent action set, rather than inherited from the path-integration construction.

## Why it blocks the target

The structural code is only a graph position if it *commutes* — same position reached by any path. No training signal or architectural constraint is named that makes it so; without it `g` degenerates into a second content code

## Best current answer

**No longer a brainstorm — but conditional.** Path integration builds the code by accumulating action displacements (`z_t = f(Wz_{t-1} + Ba_t)`), so equal total displacement lands on the same code by construction, in four implemented model families and three animal phyla; hexagonal symmetry itself follows from a third-order regularisation term implementable as a non-negativity constraint. What it does *not* do is hold on arbitrary graphs: consistent actions must exist across the family (G41), and where they do not (a bare social network) the mechanism is unavailable (Whittington et al. 2022) **And it can be imposed on a perception module rather than only on a recurrence** ([[wiki/entities/gcq.md]]): quantise the encoder's latent sequence against candidate trajectories `e_i ⊕ a_{1:n−1}` generated by applying the known actions to each codeword, and the commitment loss makes path-consistency a constraint on *what the encoder may emit*. The by-product is the reason the row matters for rollouts — a latent that is a pure function of one index and the action sum cannot accumulate prediction error, which is what flattens prediction FID over horizon where an autoregressive latent predictor degrades (Peng et al. 2025).
