# G40 — Nothing decides when to factorise and when to entangle

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** _unset — see [[wiki/priority-tasks.md]]_

## Why it blocks the target

Compositional bases are assumed to be strictly better, but they cost a composition step at every use, and a bespoke entangled code is cheaper when the task components always co-occur — grid cells demonstrably *warp* toward consistently rewarded locations, destroying transfer, and stop warping when reward configurations vary. So a system that always factorises is paying for generalisation it does not need, and one that never does cannot transfer. The same knob governs how many separate integrators to run (space × task × time) and whether a learned pairing survives a change of topology (a T-maze becoming a W-maze)

## Best current answer

**A stated rule with no controller:** factorise exactly when *the task set itself* is factorised — i.e. when components recombine across episodes. Falsifiable in animals (vary reward-configuration switch rate, watch grid warping appear and disappear); nothing implements it, and no machine measures the switch rate it would need. **A measurement now exists, and it moves the question one level up.** In mouse dorsal CA1 the two answers hold simultaneously: ~90% of cells informative about accumulated evidence code it *conjunctively* with position (entangled), while on the population manifold position and evidence are two independent gradients (factorised) — so factorisation is a property of the **geometry**, not of tuning curves, and can be scored without cell-level correspondence. Intrinsic dimensionality is the candidate controller-observable: the same circuit yields a significantly *lower*-dimensional manifold on a simpler version of the same maze, so "how many factors is this task forcing" is readable from the activity (Nieh et al. 2021, [[wiki/concepts/population-geometry.md]]). Still missing: what *acts* on that reading, and how manifolds for two tasks relate. **And the one case where the setting has been read off a brain comes out `factorise`, under conditions the stated rule says should favour entangling** (Zheng et al. 2024, [[wiki/concepts/cognitive-map.md]]): two relational structures over the *same* 12 objects — a one-day-old transition graph and lifetime semantic taxonomy — are both mapped in the hippocampal formation but in non-overlapping clusters, each effect at zero in the other's region of interest, with no conjunctive code detectable. The components always co-occur (same items, every trial) and neither was ever task-relevant, so co-occurrence is not the argument. **And the controller question — what *acts* on the reading — now has two candidate answers, both from the source that defined the measurement.** (i) *Supervision names the factors.* A two-hidden-layer network trained on MNIST digits 1–8 to output parity **and** magnitude develops abstract format (CCGP and PS above a random-geometry null) for exactly those 2 of 35 dichotomies, while shattering dimensionality stays at 0.96 — so what gets factorised is set by what the output layer is required to name, and every other variable remains decodable but entangled. The input carries no aligned structure, so this is creation, not extraction. (ii) *Volatility sets the rest.* In simulation, the value of the previous trial becomes progressively **more** abstract as the rate of latent context switches rises — the first quantitative instance of G40's own stated rule (factorise what the world re-shuffles), with the switch rate as the readable environmental parameter the rule always needed. What neither supplies is the *unsupervised* case with no naming and no reward-relevant switch: the same paper's deep Q-learning agent does make an unobserved context abstract, but only in a fraction of runs, so the knob exists and is not yet reliable (Bernardi et al. 2020, [[wiki/concepts/population-geometry.md]]) the switch takes; the source's candidate argument is *mode and timescale of acquisition*, which is a variable no machine architecture records about its own representations. This also splits the row in two — deciding to keep structures apart is worthless without something that then *selects* between them (G12), and nothing supplies that either ([[wiki/empirical-tensions.md]] T51) **And the row now has a measured price and a default** (Collins & Frank 2013, [[wiki/entities/c-ts-model.md]]): in a task where the flat solution is strictly cheaper — four conjunctive links against six hierarchical ones, and the flat single-loop network reaches criterion *faster* — humans nonetheless impose a context→task-set factorisation, identified per subject by a reaction-time switch cost measured before the transfer phase and never shown to the model fits (`r = 0.39, p = 0.019` against the size of their transfer effect). So the biological setting of this knob is **factorise by default**, and the bet is on transfer the learner cannot know is coming. The row's stated rule (factorise when the task set itself is factorised) is therefore wrong as a description: the switch here is not driven by observed recombination. It is also the first case where the cost of over-factorising is measured rather than argued — a new situation that partially matches a stored factor produces systematic wrong-rule errors that the flat learner does not make. **And a continuous dial for the same knob, settable per query.** Contextualization weights `(κ_o, κ_c)` interpolate between a fully factorised filler code (`κ_c = 0`) and one with role co-occurrence entangled into it, at a cost measurable as dot-product variance; because memory is encoded once at fixed `κ⁻` and the probe re-weighted freely, the setting is a *query-time* choice rather than a training-time one. Still nothing sets it adaptively — but what would have to be measured is now concrete: how much of the current retrieval's discriminative work falls on structure versus on attributes. **The same knob in its rule-versus-exception form, with a measured switching point and no controller** (Hupkes et al. 2020, [[wiki/entities/pcfg-set.md]]): insert exceptions to an otherwise exceptionless rule at 0.01 / 0.05 / 0.1 / 0.5% of a function's occurrences and all three seq2seq architectures apply the rule anyway below 0.5% and none of them do at 0.5%, while below 0.01% two of the three never learn the exception at all. The dial exists, it is sharp, and it is set entirely by the *data* — nothing in any of the models measures its own exception rate or decides where to sit on the curve. It also shows over-generalising has a distinct failure from over-entangling: one architecture, having detected that a case is exceptional, stops producing the rule output **without** starting to produce the memorised one, for the rest of training.
