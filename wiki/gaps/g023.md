# G23 — Machine priors are unconditional; a prior needs an entry test

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A prior carries a learned entry test that admits the entities it applies to and rejects the rest, and the gated version outperforms its ungated twin on inputs outside the prior's domain.

## Why it blocks the target

A core system applies only to a subset of entities *and* only to a subset of their properties — a pile of sand fails cohesion and never enters the object system. Every inductive bias the wiki has (convolution's translation prior, attention's adjacency, a plasticity rule) applies to all input unconditionally, so a prior that is wrong for part of the domain cannot be locally disabled; it is smeared over everything. Without an entry test, adding more priors monotonically adds more misapplied constraints, which is why the architecture lever (G16) does not obviously scale by stacking

## Best current answer

Core systems' selectivity, stated as a property, with no computational account of what evaluates the entry condition. Spelke & Kinzler 2007 add the strongest *reason* for gating: the geometry system applies to extended surfaces and not to movable object arrays, because movable things do not predict where you are — so an ungated version of the same prior would be actively wrong, not merely wasteful. **(brainstorm)** The gated form also supplies the routing policy G12 asks for: the test that admits an observation to a fragment *is* the router. **First implemented near-relative**, gating hypotheses rather than entities: FEASIBILIZE ([[wiki/entities/hbtom.md]]) zeroes out goals the current world state makes unreachable and renormalises the rest before the prior is used, so the preference prior is locally disabled without being unlearned — a mask on a categorical latent, cheap enough for any softmax head, and the condition is computed from the state rather than declared **And the object system's entry test is now computed rather than stipulated** (Venkatesh et al. 2025): cohesion-under-applied-force — the very condition Spelke's account presupposes and never specifies — is recovered from 7k hours of unlabeled video by poking a flow world model and clustering the co-response, beating a *supervised* segmenter on a benchmark built to Spelke's criteria with no segmentation label at any point ([[wiki/entities/spelkenet.md]]). This is the first evidence in the wiki that an entry condition can be learned from passive observation rather than installed. The residual is the gating itself: the detector says which pixels cohere, not which downstream system should receive them, so the router half of this row is untouched. **And the row has a scaling statement now, which makes stacking priors non-monotonic** (Pfister & Jud 2025, [[wiki/concepts/problem-framing.md]]): every installed regularity assumption buys efficiency on a smaller subset of worlds while raising the probability of a mismatch with the world actually met, so a prior needs not only an entry test but a *withdrawal* mechanism — and the wiki has nowhere to put one, since no architecture here can mark an installed constraint as failing rather than merely being outvoted.
