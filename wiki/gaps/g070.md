# G70 — Every induced program in the wiki is a straight-line composition; nothing induces a loop, and the cost is that no program can extrapolate a count

**Status:** `PARTIAL`  
**Kind:** `part`  
**Level:** `L0`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** An inducer emits a program containing a loop or recursion whose trip count is not fixed at synthesis time, and extrapolates a count beyond every training instance — the case unrolling cannot reach.

## Why it blocks the target

A transformation applied *until a condition holds* — translate the line across the grid until the border, repeat the motif to fill the space — has no fixed-length representation. Every inducer here emits a fixed sequence and must therefore *unroll*: `n` copies of the same clause, chosen from the training examples, which silently caps the test instance at `≤ n` repetitions. This is not a search-budget problem; the hypothesis class has no `Do Until`, `Repeat While` or recursion in it, so the correct program is not merely hard to find but inexpressible. It also makes the composition depth a *data* parameter rather than a program parameter, which is the opposite of what productivity requires

## Best current answer

**Nothing on the ARC-shaped side** (one system elsewhere does it under trace supervision — see the end of this section). [[wiki/entities/ilp-arc-synthesizer.md]] names the hole explicitly and defers it to future work, after showing a task (`0a938d79`) that its unrolled program solves only because the test grid happens to need no more translations than the training grids did. [[wiki/entities/neo-neural-theorizer.md]] composes ≤8 codebook symbols by concatenation with no control flow at all; [[wiki/entities/bayesian-program-learning.md]]'s programs have a fixed part/sub-part structure sampled from the prior; [[wiki/entities/aixi.md]] has the whole computable class and no tractable search inside it. The host languages are Turing-complete in every case — Prolog, an executor network, a probabilistic λ-calculus — so this is a restriction on the *induced* class, imposed to keep the search finite. Note the biological side has the opposite shape: [[wiki/concepts/path-integration.md]] iterates an update rule an unbounded number of times by construction, but has no termination condition either **The end-to-end side of the same hole, measured** (Hupkes et al. 2020, [[wiki/entities/pcfg-set.md]]): where an inducer unrolls a fixed number of clauses, a trained seq2seq model holds a *length-indexed family of behaviours* in place of one operator. Trained on string arguments of length ≤5, LSTMS2S accuracy on every function drops to **exactly 0 at length 6** across all seeds; ConvS2S and Transformer decay smoothly to ~12 and ~9. A cliff at the training boundary is competence, not performance: `copy` was never acquired as a function of a variable-length argument. Productivity on held-out *sequence* lengths shows the same shape (0.30 / 0.31 / 0.50 against task accuracies of 0.79 / 0.85 / 0.92), and early end-of-sequence emission accounts for only 22 / 6 / 8% of it, so the cause is the missing iteration, not truncated decoding. **Now an authored eval axis rather than an incidental hole** ([[wiki/entities/arc-agi-2.md]]): *multi-step compositional reasoning* tasks are designed so the state after step `N` depends on the outcome of step `N−1`, with the paper's own statement that it is "virtually impossible to predict the position of object `N+1` without executing the previous `N` steps" (task `cbebaa4b`). A benchmark that deliberately populates itself with unrollable dependency chains is the first instrument in the wiki that would *score* this gap rather than merely exhibit it — except that it returns one exact-match number and no per-axis subscore, so the attribution is the authors' intuition.

**The first inducer whose emitted program has an unbounded trip count** ([[wiki/entities/recursive-npi.md]], Cai, Shin & Song 2017). A Neural Programmer-Interpreter trained on execution traces in which the program *calls itself* instead of looping: the controller's hidden state is zeroed and the caller's context stacked at every call, so a tail call erases the length-dependent history and "there is no concept of length relevant to the problem". Trained on 100 traces of arrays of length ≤2 it sorts length-90 arrays at 100%; 4 traces of length-5 arrays give quicksort to length 70 where the non-recursive control falls from 73.3% at length 11 to 0% at 70; one trace from a 5-node graph gives topological sort to 70 vertices against 6.7% at size 5 non-recursively. And the count is not merely extrapolated but **proved**: recursion makes the set of valid step-input sequences within one call finite, so running the model on 20,181 addition problems, 73 graphs, or a single 10-element array certifies behaviour on inputs of unbounded size — the wiki's only proof of perfect generalization for a learned program.

**Why this is `PARTIAL` and not `CLOSED`.** The letter of the `Closes when` is met; the spirit is not settled, and the residual is one thing. **The recursion is authored, not induced**: it arrives as hand-written recursive traces over a hand-written program set, with per-*step* supervision (step input → step output), so what is demonstrated is that the hypothesis class can *hold* an unbounded trip count, not that anything discovers one from input/output pairs. The authors name training "with only partial or non-recursive traces" as future work, and the partial-recursion ablation shows the abstraction cannot be half-installed: making one of bubble sort's three length-dependent loops recursive moves accuracy from 6.7% to 23% at length 3 and leaves 0% at length 8. A second restriction is the verification half's, stated by the authors: the base-case space must be finite and enumerable, which rules out perceptual inputs (MNIST digits, speech) — so on ARC-shaped tasks the proof machinery, not just the search, would have to be replaced.

## Status

`PARTIAL` — a system exists whose induced program recurses with an input-dependent trip count and is *verified* to generalize perfectly, but the recursion is supplied by the supervision (recursive execution traces over an authored program set) rather than discovered, and the verification procedure requires a finite base-case space. The row stays open on the discovery half.
