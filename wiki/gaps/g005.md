# G5 — No joint discover-and-navigate loop

**Status:** `PARTIAL`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** The predict-fuse-relax loop revises `W` — the variable set and its structure, not only node values — during acting, in a domain larger than AutoToM's agent models, with an offline-`W` control that fails the same task.

## Why it blocks the target

Hard tasks give no discovery-then-use phase separation: the graph estimate must update *while* it is being searched. Architectures that assume a fixed model at inference time cannot express this

## Best current answer

**Half-built.** Butz 2016's predictive processing loop runs predict → fuse → relax-to-consistency every cycle *while* acting, so the instance-level estimate is revised during navigation with no discovery-then-use phase. The meta level is untouched: `W` still adapts on a slower, effectively offline schedule, so the loop is joint over node states and not over structure. **One system now runs the loop over *structure* as well, in a small domain**: [[wiki/entities/autotom.md]]'s embodied-assistance arm re-runs agent-model discovery at every timestep while the helper acts, carrying the goal posterior across steps by Sequential Monte Carlo — so the model's variable set, not only its node values, is revised during navigation. It is a 27.7% speedup against 6.8% for the same planner fed a large language model's goal guess. Two limits keep the row `PARTIAL`: the thing re-discovered is which of four authored variable types to instantiate, and the agent's own actions do not enter the model it is inferring — the helper observes and assists, it does not act to disambiguate
