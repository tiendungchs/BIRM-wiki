# G37 — Nothing decides which stored structure applies to the current situation

**Status:** `PARTIAL`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** Retrieval is run against a *discovered* schema library rather than two given graphs, and reports precision at the operating point rather than AUROC, with a certificate that flags its own misses (T22).

## Why it blocks the target

Every schema mechanism in the wiki assumes retrieval and none supplies it: instance binding must first find the right meta-graph fragment, an event schema must test its precondition against the state, a core-knowledge system must decide whether the input is in its domain, and analogy must align two relational skeletons. Stated as a graph query this is subgraph isomorphism — NP-complete, exponential in practice (VF2/RI fall below 60% success at query size > 30), so a large schema library is unusable unless retrieval is sub-exponential

## Best current answer

**Partial and geometric.** Embed graphs so that containment *is* the geometry (`z_q ≼ z_u` componentwise ⟺ `G_q ⊆ G_u`) and the query becomes a coordinate comparison: median 95.5 AUROC, 0.03 s vs. 7.5–25.9 s for exact search, with transitivity, anti-symmetry and closure under intersection satisfied by construction, and zero-shot transfer from random graphs to chemistry/biology/vision graphs ([[wiki/entities/neuromatch.md]]). Three things are missing. (i) **No certificate** — an approximate matcher cannot flag its own errors, and the only ground truth is the exponential method it replaces. (ii) **Precision, not AUROC, is the deployment metric** — matches are rare, and at 97.9 AUROC the reported confusion matrix gives 49% precision ([[wiki/empirical-tensions.md]] T22). (iii) **Both graphs are given** — retrieval has never been run against a *discovered* library, so it is untested exactly where the framing needs it. **And a second, statistical answer to the same question** (Heald et al. 2021): rather than testing structural containment, maintain a posterior over which stored model is *generating* the current data — `p(context) ∝ p(cue∣context)·p(context∣previous)·p(feedback∣state)` — which is graded rather than binary, sequential (last step's posterior is this step's prior), and uniquely also decides **when no stored structure applies** and a new one must be allocated. Confirmed behaviourally: all memories update in proportion to responsibility, not winner-take-all (cue `p=3.8×10⁻³`, feedback `p=1.26×10⁻⁴`, additive). It buys this with a scalar per stored structure — no internal structure to match against. **A third answer, mechanistic rather than algorithmic:** an auto-associative network addressed by a weak cue input settles to the nearest stored attractor, so retrieval is relaxation and costs one settling pass regardless of library size — CA3 lesions and CA3 NMDA-receptor knockouts collapse recall specifically when only 1–2 of 4 trained cues remain (Yassa & Stark 2011). It supplies what the other two lack (no search, no explicit comparison) and lacks what they have: no certificate, no posterior, and no way to tell a correct completion from a confident wrong one — the aging failure mode is exactly this. **The relaxation answer's two worst properties are both removable** ([[wiki/entities/vector-hash.md]]): if the attractors are prestructured and content-free rather than content-defined, the basins are provably convex, uniform and spurious-free, so retrieval-by-relaxation stops being content-dependent; and the library size becomes exponential in the network size rather than linear in fan-in. It also supplies the missing certificate in weak form — mean store activity separates familiar from novel cues with a two-threshold classifier, i.e. the store can report *"nothing applies"* without a posterior. What it gives up is the thing retrieval is for: addresses are assigned at random, so a retrieved item's neighbours in the store are unrelated to it, and no query can ask for "structures like this one". **And it is the only one of the three with a capacity bound**: `p_max ≈ k·C/(a ln(1/a))` — ~36,000 patterns at rat CA3 parameters — so retrieval-by-relaxation is the one answer here whose library size is *derivable* rather than assumed, and overload degrades it catastrophically (past capacity, nearly nothing retrieves) rather than gracefully (Rolls 2013) **And the row is narrower than it looked:** retrieval answers *which* structure, not *where on it the situation sits* — the spatial literature dissociates context retrieval from orientation, so every answer above stops one operation short of usability (G39, [[wiki/concepts/cognitive-map.md]]). **Third answer, and the first with a neural read-out:** the same statistical retrieval run on hippocampal maps, where the responsibility posterior is expressed as *remapping* and its uncertainty is directly visible as heterogeneity across the population (Sanders et al. 2020). Two transferable additions. (a) **Orientation is nested inside retrieval, not after it** — each candidate map is aligned by `φ_k = argmax_φ P(y − φ ∣ Y_k)` before its likelihood is compared, so a stored structure that fits badly *under its own best alignment* is what triggers allocation. (b) **Tolerance is per-feature and learned from within-state variance**, so retrieval is not a similarity test: a feature that has historically varied in this context does not trigger a new allocation when it varies again (confirmed, Plitt & Giocomo 2019). Still missing: the proposal step. Both this and the geometric answer assume the candidate set is given, and the source calls its own account "an analytical heuristic rather than an algorithmic theory" **Fourth answer, and the only one that is not a computation at all** ([[wiki/entities/context-modular-memory-network.md]], Podlaski et al. 2025): supply the context as an external discrete signal and let it act as a binary mask `a_i^k a_j^k c_ij^k` on the connectivity, so the non-applicable structures are *deleted from the dynamics* rather than out-competed in it. Selection is `O(1)` in library size with no comparison step, no posterior and no cue-matching; the accessible memories' basins grow while the inaccessible ones' stability goes to zero. What this contributes to the row is a price list rather than a mechanism: the accessible fraction falls as `1/s` exactly as capacity rises, memory content can be moved into the mask entirely (a random weight matrix plus the right mask stores arbitrary patterns, [[wiki/empirical-tensions.md]] T59), and the mask itself is cheap to write (one signed comparison per synapse). What it does not do — and states plainly — is say where the context signal comes from: retrieval is turned into a *precondition*, so the row's question is relocated to a controller that the model does not contain, and the authors' own scaling estimate for that controller (`s·N` for synaptic gating) is larger than the memory it addresses. **That controller is now measured** ([[wiki/entities/mediodorsal-thalamus.md]], Rikhye et al. 2018): the context signal is not supplied from outside at all but **pooled from the population it gates** — >75% of the mediodorsal thalamus's delay-period variance is explained by prefrontal cue-selective cells, and suppressing the cortical terminals removes the thalamic context selectivity — and returned as two oppositely signed channels, one sustaining the in-context representation and one suppressing the out-of-context one via cortical interneurons. So the sixth answer to this row is a *loop*: `c = f(h)` with `f` a wide non-recurrent pooling, `g(c)` multiplying `h` and its reachability. It costs one low-dimensional relay rather than `s·N`, needs no task label and no posterior, and buys the weight protection as a by-product. Its limit is the price of having no inference: a variable pooled from the content cells cannot represent a context those cells have never expressed, cannot allocate a new one, and carries no uncertainty — which is exactly the 4–8-trial cost paid on first entry to a new block. **And the missing arrow is now named:** the controller has no direct axons into the episodic store, but reaches it through nucleus reuniens, and what that route carries is a *goal-conditioned future path* rather than a retrieval query ([[wiki/entities/nucleus-reuniens.md]]) — so the biological version of this operation may not be a query at all, but a constraint written into the store whose own dynamics then produce the match. **A fifth answer, and the first where the retrieved object is a policy** ([[wiki/entities/c-ts-model.md]]): a Chinese-restaurant posterior over task-sets, where a *new* context is assigned to an existing rule in proportion to that rule's popularity **across contexts** — so retrieval generalises to situations never seen, which the scalar-state version was never tested on. Two things it adds to the row. (i) The prior is not a hyperparameter: sweeping the context→prefrontal projection from random to one-to-one moves the fitted `α` (`r = 0.76`), so the allocate-vs-reuse setting is a wiring statistic. (ii) It prices the failure mode the graded answers hide — committing to a partially-matching stored rule is *worse* than having no match at all, because half the stimuli confirm it (an overlapping new context recruits a fresh rule at `E(N) = 0.84` against `0.99` for an incongruent one, and humans show the corresponding excess of neglect-context errors). Its own limit: similarity between two contexts is never directly observable, only one stimulus–action–outcome slice per trial, so retrieval evidence accumulates far more slowly than in any perceptual-clustering version **A third answer, cheaper than both, that changes the code instead of the comparator.** A Holographic Reduced Representation encodes a nested relational episode as one fixed-width vector, and *contextualization* — blending each filler with the typical fillers of the other roles it occupies — makes role alignment a **surface feature**, so a single dot product reproduces the full MAC/FAC / SME ordering `LS > AN^cm > AN > SS > FA` in 100/100 runs at `n`=2048, with the salience of structure re-tunable per query by re-weighting only the probe. It inherits the same no-certificate hole, degrades as episodes grow (similarity is a sum of feature matches), and fails outright when two entities fill the same set of roles. **And the second stage — the alignment itself — now has the same treatment.** Superposing into each element's code the *labels* of the higher-level roles it fills makes the correspondence an `argmax` of a normalised binary dot product: `O(n·n')`–`O(n²)` against SME's `O(n²)`–`O(n!)` and ACME's `O(n⁴)`, correct on all five similarity types of the standard probe set and on Water-Flow/Heat-Flow, Solar-System/Atom and Schools, reliable from `N ≈ 1000`, with elements scoring below chance overlap dropping out as a free relevance filter and candidate inferences filtered by fitting the whole target better than any of its parts. Same three holes remain — no certificate, hand-authored episodes, and a structural context that is a *set* of roles and therefore blind to their arrangement (Slipchenko & Rachkovskij 2009, [[wiki/concepts/analogical-mapping.md]]). **And the row's oldest working answer, which supplies the certificate in the one form nobody here has tried — a *soundness argument* rather than an error estimate** (Gentner & Forbus 1991, [[wiki/entities/macfac.md]]): filter not on an approximation of the matcher's *answer* but on a cheap over-estimate of its *search-space size*. The dot product of functor-occurrence counts over-counts the local match hypotheses SME would generate, and few local matches entail that no large global interpretation exists, so the filter's errors are wasted second-stage calls and never dropped candidates — no training, no ground truth, and the guarantee holds at any library size. Measured filter ratio: 3.3 candidates surveyed, 1.5 accepted, from a 36-item pool. Three things it does not fix. (i) It **cannot say nothing applies** — both selectors are relative (best plus 10%), and an absolute threshold is omitted because the authors "have not yet found good constraints" on one, which is the same missing quantity as G38. (ii) The bound is on the *count* of match hypotheses, not on their groundedness or 1:1 compatibility, so it under-predicts interpretation quality in exactly the two ways the source names. (iii) It is structure-blind by design and defended as such ([[wiki/empirical-tensions.md]] T197), so it answers *which stored structure is worth aligning against* and never *which one applies*. **The journal version (Forbus, Gentner & Law 1995) adds three things this row has been missing.** (a) **The first constraint in the row on what a cheap filter's statistic may contain**, obtained by ablation over the whole design space rather than argued: attribute-only content vectors have *no* viable setting at any pair of selector widths (relational content never cues retrieval), and relation-only content vectors are viable only where the filter passes ~half of memory (the relational vocabulary does not discriminate) — so a first-stage statistic must span both item-level and relation-level content, which is directly testable by ablation on every learned filter here. (b) **A candidate for the proposal step the row says is assumed** — run the two stages *iteratively*, re-weighting the components of the probe's own content vector according to which aspects carried the previous round's partial matches, so the candidate set is regenerated by editing the query rather than assumed given; unimplemented, but it is the only proposal in the wiki that closes that loop without a second mechanism. (c) **An error-asymmetry rule that justifies a tight rather than a loose match criterion**: in a large pool a false positive costs more than a false negative *because* retrieval is iterative (a miss is recoverable by re-representing the probe; a false positive has already spent the expensive stage), and the measurement behind it is that stripping ARCS's WordNet-graded predicate similarity — leaving identical-predicate matching only — repairs most of its false positives without touching its architecture. Two limits also harden: the retrieval stage is **empirically impenetrable** (instructing people to seek relational remindings halves surface remindings and produces no more analogies), so a surface-driven index cannot be *queried* for structure — only its output filtered; and the model is purely exemplar-based, so the inter-item competition effect that heightens structural similarity's influence (Wharton et al. 1994) is inexpressible when each candidate is scored independently.  **And now a number for how badly it goes wrong when nothing does it well** ([[wiki/entities/cn-dpm.md]], Lee et al. 2020). A task-free continual learner that allocates one neural expert per detected regime and gates by per-expert generative likelihood reports its own retrieval accuracy against ground-truth task labels — the only such measurement in the wiki, because every other allocate-vs-reuse account reads retrieval quality off a behavioural fit. The stored components are intact (classifier accuracy 88.20% at the end of its own task, **88.20%** after every later task) and the gate is right **48.18%** of the time over 5 components and **31.14%** over 20, which takes end-to-end accuracy to 45.21%. Two structural findings come with it: retrieval accuracy *degrades with library size*, and the gate **cannot be a learned router**, because a router over a growing component set is an online classifier and forgets exactly like the learner it routes for — so this gap cannot be closed by training a selector, only by making the components' own likelihoods discriminable. **The row's baseline case, stated by an architecture that declines to attempt it** (Rusu et al. 2016, [[wiki/entities/progressive-neural-networks.md]]): a progressive network retains every task's solution exactly and lists "choosing which column to use for inference requires knowledge of the task label" as an unsolved limitation. Storage at zero loss with retrieval left entirely to an oracle is the clean statement of this gap — and CN-DPM, which does attempt the gate on the same family, is what turns it into a number (48.18% at five components).
