# G99 — No architecture in the wiki can call a module's *operation* on an argument from outside the module's own domain; every transfer mechanism here moves representations, none exposes an operator

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** One module's operation is called on an argument from outside its own domain, with the operator exposed rather than a representation copied, and the borrowed operator does useful work on the foreign type.

## Why it blocks the target

Hauser, Chomsky & Fitch 2002 propose that the human generative capacity arose not by inventing a recursive operator but by a **modular, domain-specific, impenetrable** operator *becoming penetrable* — the architectural event is a change in who may call an existing routine, not the appearance of a new part. The wiki's structural modules already contain unbounded-iteration primitives ([[wiki/concepts/path-integration.md]] applies its update rule an arbitrary number of times by construction) while every induced program in the wiki lacks exactly that primitive (`G70`). The operator exists in the architecture and is unreachable from anywhere else in it

## Best current answer

**Nothing.** Cross-domain transfer in the wiki is representational throughout: a shared code reused on new content ([[wiki/concepts/abstract-structural-codes.md]]), a map transported to a new task ([[wiki/concepts/nonspatial-maps.md]]), a library of primitives enumerated by a search ([[wiki/concepts/program-induction.md]]). None of these is a module *lending its update rule* to a caller with a differently-typed argument. `G21` is the adjacent row and is not the same request: it asks for the outputs of two modules to be combined, this one asks for one module's procedure to be invoked on the other's data. The nearest partial is `G23`'s entry test read in reverse — relax the type check on the operator while retaining it on the module's priors — which is stated as a proposal on [[wiki/concepts/discrete-infinity.md]] and implemented nowhere **The nearest thing to a proposal, stated and never run** ([[wiki/entities/neural-module-networks.md]]): Andreas et al. 2016 observe that once trained, their modules can be assembled by *any* outside caller with no natural language involved — "visual SQL", `IS(cat) AND NOT(IS(dog))`, and explicitly the mixed case `IS(cat) and date > 2014-11-5`. That is a learned module's operation being invoked by a caller outside the system that trained it, which is this row's request. What keeps it short: the type system is closed (three data types, five signatures), so a caller may only hand a module an argument of the type it was declared over — and the mixed example is precisely the case the type check forbids. The source does not say how a foreign type would be admitted, and runs no such experiment.
