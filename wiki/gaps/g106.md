# G106 — A superposition-of-bindings code over a fully crossed stimulus set is linearly dependent by construction, and nothing in the wiki checks for it

**Status:** `OPEN`  
**Kind:** `part`  
**Level:** `L3`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** The encoded-item matrix of a structural code is reported alongside its rank on a factorial task set — i.e. a model states whether the structures it must tell apart admit an annihilator — and either the rank deficiency is shown not to bind the read-out, or a code is exhibited that keeps a fully crossed set independent at stated width.

## Why it blocks the target

Smolensky 1990 (Def 3.15, Thm 3.16) gives a condition on a *set of structures*, prior to any choice of vectors: a sequence `s^(k)` has an **annihilator** if there are reals `a^(k)`, not all zero, with `Σ_{k : f/r ∈ β(s^(k))} a^(k) = 0` for every filler/role binding. If one exists, the tensor-product representations `{Ψ(s^(k))}` are linearly dependent **for every choice of filler and role vectors, at every dimension**, and cannot be associated with arbitrary targets even by Widrow-Hoff. The canonical case is the smallest possible factorial grid: `{ax, bx, ay, by}` under positional roles, annihilator `(+1, −1, −1, +1)` — the parity contrast, with every binding covered twice at opposite signs. `{ax, bx, ay}` has none.

This is a different kind of limit from everything else the wiki prices. Dot-product variance ([[wiki/concepts/vector-symbolic-binding.md]]), the `d_dot` orthogonality cap ([[wiki/concepts/fast-weight-programming.md]]) and the rank-`d` retrieval bound ([[wiki/concepts/retrieval-capacity.md]]) are all statistical or dimensional and are bought off with more width. This one is algebraic: a rank deficiency in the item set that survives any encoding.

It blocks the target because **the wiki's relational benchmarks are fully crossed grids by design** — a Raven's matrix is attribute × position, a [[wiki/entities/pgm.md]] item is `(relation, object, attribute)` fully crossed, an ARC task set varies transformation against object property. A code that superposes role–filler bindings over such a set is exactly the failing configuration, so a linear read-out over it cannot assign independent values to the cells. Whether that is *the* reason these benchmarks resist the models built on such codes is unknown — and it is cheap to check, since it needs only the rank of the encoded item matrix, no training and no held-out set. Nobody in the wiki computes it.

## Best current answer

**The escape route is named but unanalysed.** Smolensky's own conclusion says content-addressed storage of structures will need **hidden units capturing higher-order conjunctions** beyond the second-order product, the annihilator case being the clean example — so the failure is specific to the *rank* of a second-order representation, not to conjunctive coding as such. That is consistent with the wiki's discovery-side gap `G105`: what is missing on both sides is an `n`-ary term. No source here computes the rank of an encoded benchmark, states an annihilator for a real task set, or reports what a rank-deficient code costs a downstream read-out in accuracy.
