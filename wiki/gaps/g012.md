# G12 — No routing policy between structure types

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A learned arbitrator selects the structure type at query time on inputs where a fixed heuristic such as a symmetry-score threshold provably misroutes.

## Why it blocks the target

Given a metric/transition-sampled module and a declarative/relational one, nothing decides which structure goes where. The arbitration is a prerequisite for G11's second mechanism to be usable at all **The wiki's first *running* router, and it is one line of code** ([[wiki/entities/corethink-compositional-reasoner.md]]): an input whose symmetry score exceeds 0.70 is sent to a rule-based jigsaw solver and bypasses the LLM entirely. A hand-set scalar on a hand-chosen statistic covering exactly one pattern family — but it shows the payoff a router buys is **cost** at least as much as accuracy (a symmetry task never pays for a frontier-model call), which is a dimension every framing of this row above states in accuracy terms only.

## Best current answer

— . **The row now has a biological existence proof for the *sorting* and still nothing for the *routing*** (Zheng et al. 2024, [[wiki/concepts/cognitive-map.md]]): a transition-sampled structure and a taxonomic one over the same objects end up in different, non-overlapping parts of the hippocampal formation, so the brain does place structure types in separate territory — but what reads the right one at query time is unaddressed, and the sorting itself may be a by-product of a resolution gradient (G38) rather than a routing decision. **The level-of-abstraction analogue of this gap now has an answer that dissolves it**: frontal cortex does not route between orders of policy at all — bands for 1st- and 2nd-order rules are both engaged above baseline from the first trial of a novel problem, and the band whose order is absent from the reward table *declines* over learning while the other is sustained, so the selection is done by attenuating unrewarded depths rather than by choosing one (Badre et al. 2010, [[wiki/concepts/policy-abstraction-hierarchy.md]]). Whether the same run-all-and-prune policy is affordable across structure *types* rather than depths is untested. **A measured cost for having no router, at the level of relational vocabulary** (Bortoletto et al. 2023, [[wiki/entities/irene.md]]): on the Baby Intuitions tasks, local-adjacency edges alone give 98.0 on Multi-Agent and 99.4 on Irrational Agent but 31.8/37.2 on path- and time-efficiency; remote-comparison edges alone give the reverse; the union that must be handed to the model to cover both is optimal on neither (74.9 / 85.7). The right edge type is task-dependent, the selection is not learnable inside the architecture, and the price of the compromise is quantified. **The gap also shows up as a leaderboard artefact**: on ARC-AGI-1, program synthesis and test-time-trained transduction each solve ≈40% and the two sets are *significantly distinct*, so every 2024 state-of-the-art entry runs both and takes the union — paying the sum of two solvers because nothing predicts which one a task needs (Chollet et al. 2024, [[wiki/concepts/test-time-training.md]]) **The one literature that studies routing as its own object arrives with a taxonomy and an unwelcome result** (Fedus, Dean & Zoph 2022, [[wiki/concepts/sparse-expert-routing.md]]): a router can take its top-`k` along the expert axis, along the token axis (which balances load by construction and yields adaptive computation for free), or globally by linear assignment / optimal transport — four mechanisms this row had none of. But every specialisation ever *observed* in a trained router is lexical, perceptual or modality-level, never relational; and a **fixed hash of the input token id**, with no learning and no context, is competitive with learned routing (`T296`). So the field's largest deployment of learned routing supplies this row with mechanism and with a warning: at token granularity the learned router may be approximating a function of token identity, which is not the query-time structure-type selection this row asks for. The survey also names the untried quadrant — token proposes, expert disposes, an `O(T·k)` stable matching rather than a global assignment. **And the wiki's one architecture where the routing granularity is right, obtained by not learning the router at all** (Andreas et al. 2016, [[wiki/entities/neural-module-networks.md]]): the routed unit is a *sub-question* rather than a token, the selected modules are heterogeneous and typed, and the specialisations that emerge are relational (`combine[and]`, `re-attend[above]`) — the first relational module-level specialisation in the wiki, and evidence that the mixture-of-experts negative result above is about granularity or arity rather than about routing as such. What supplies the layout is a Stanford dependency parser, unlearned and un-tuned, and the source's own error analysis puts the failures there (80–90% parse accuracy on simple questions, worse on the compositional ones): so this row gets a demonstration that a correct decomposition pays and no learned mechanism for producing one. **And a negative result about what a learned router at token granularity is doing** (Fedus, Zoph & Shazeer 2022, [[wiki/entities/switch-transformer.md]]): replacing the routing argmax with a *sample* from the router's own softmax costs 0.10 negative-log-perplexity (−1.570 vs −1.471), and no exploration scheme beats deterministic exploitation — so the largest deployed router has nothing to explore, which is what one expects if its decision is close to a function of token identity (`T296`) rather than a query-time selection among structure types. The same source supplies this row's first **abstention** datapoint: iteratively rerouting tokens that overflow their chosen expert to a second choice, until virtually none is dropped, buys nothing on quality or stability — a wrong module is worse than no module, which is a design constraint on any arbitrator this row eventually gets. **And the wiki's first router whose input is not the thing being routed** (Goyal et al. 2019, [[wiki/entities/rims.md]]): each module computes its selection query from **its own recurrent hidden state** with private weights, attends over the input with a **null row appended**, and is activated if it puts less mass on that null row than its competitors. Three things this row did not have follow. (a) **Context-dependence by construction** — the same input activates different modules depending on history, which is precisely the property `T296` says has never been demonstrated for any router measured at scale. (b) **Abstention as the default**, which is the design constraint this row already recorded from the Switch overflow result (a wrong module is worse than none): comparing against a null option makes top-`k` a reserve-price test rather than a ranking, so "nothing here applies" is representable. (c) **No load-balance machinery is needed or reported**, because there is no shared router matrix to collapse through. What it still does not supply is the row's actual target: the modules are selected by *relevance to the current input*, not by *structure type*, the vertex count `k_T` and traversal width `k_A` are hand-set, and the specialisations that emerge are temporal phase and image region — never relational, and worse, **decaying over training** as prediction improves. There is also no random-routing control, so this architecture cannot separate "the selection is right" from "the sparsity is enough" any better than the mixture-of-experts literature can.
