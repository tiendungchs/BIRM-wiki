# G97 — The read-out of a sparse store is dense, and that is where the interference comes back

**Status:** `OPEN`  
**Kind:** `part`  
**Level:** `L2`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A sparse store is read through a decoder stage distinct from the model it feeds, and the interference measured at the dense read-out drops as a result.

## Why it blocks the target

Every fast store in the wiki removes interference at the *write* — sparse codes, hashed keys, expansion recoding — and then reads back through a dense decoder into a dense model state. The CLS argument says this undoes the work: a dense receiving population participates in very many memories, so learning to decode each novel sparse code has a substantial chance of corrupting an old one. Biology's answer is an interposed **sparse, invertible** stage (CA1) that must additionally be *componential*, so that unseen patterns are decoded as recombinations of existing elements — and the review is explicit that no CLS model learns this code, all of them install it by design and pretraining

## Best current answer

**Nothing.** No architecture in the wiki has a decoder stage distinct from the model it feeds; retrieval-augmented and memory-augmented systems read the store straight into the residual stream

## From

Named and argued in O'Reilly et al. 2011 (after McClelland & Goddard 1997); [[wiki/concepts/complementary-learning-systems.md]], [[wiki/concepts/compositionality.md]], [[wiki/empirical-tensions.md]] T33. Composes with the fan-out constraint of [[wiki/entities/rolls-treves-hippocampal-model.md]] — the return path is polysynaptic *and* every stage of it must stay sparse
