# G83 — Every structure-discovery mechanism in the wiki outputs a structure; none outputs a reusable map between structures

**Status:** `PARTIAL`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** _unset — see [[wiki/priority-tasks.md]]_

## Why it blocks the target

A reasoning system that meets the same relational problem in a new context has two options: re-discover the graph from scratch in that context, or apply a stored deformation to the graph it already has. Everything in the wiki does the first — a fitted effective connectome is refitted per state ([[wiki/concepts/effective-connectivity.md]]), a clone-structured hidden Markov model is re-run per environment, a world model is re-estimated per action space. Nothing holds an operator whose *input and output are both graphs*, so context-change is always paid for at the price of structure learning rather than at the price of applying a stored transform, and there is no representation in which "the same reorganisation happened under a different task" is even statable

## Best current answer

**First instance, and it is more favourable than expected** (Yoo et al. 2022, [[wiki/concepts/connectome-state-transformation.md]]): a rank-10 linear operator, estimated from ~45–100 people's paired rest/task connectomes, carries an **unseen** individual's 35,778-edge resting graph into their task graph well enough for 74% seven-way state identification, with within-individual similarity exceeding cross-individual — so the map is population-level while the graph it acts on stays individual. Three things it does not supply: the map is between two *descriptive* (symmetric, unsigned) graphs, the cross-basis correspondence it needs is done greedily by spatial similarity and admitted to be an expedient (G37, [[wiki/concepts/subgraph-matching.md]]), and the context label must be given — nothing composes two such operators, inverts one, or learns a new one from a single example
