# G2 — De-aliasing without a hand-built state space

**Status:** `PARTIAL`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A model gives two identical observations at distinct graph positions distinct persistent codes in a domain where path context, entity type and event-set membership are all withheld from the designer, and the separation survives a raised alias rate out of distribution.

## Why it blocks the target

The same observation recurs at structurally distinct graph positions; without path-sensitive identity the model merges nodes that must stay distinct

## Best current answer

Clone cells, or identity carried by path-integrated `g`; sparse conjunctive coding in the fast store gives distinct codes to repeated observations; **module membership as a free identity tag** — 10-month-olds fail to individuate two entities typed by the same core system (duck/truck) and succeed when they are typed by different ones (ball/doll), so a bank of entry-gated priors de-aliases without path context. **Third free tag:**  an *event* is a **set** of co-active predictive encodings, so two identical observations sitting in different active sets are different events without any path integration. **Fourth answer, and the only one that is a tunable circuit rather than a tag:** expansion recoding through a sparse layer whose transfer function is *steeper than identity* — dentate granule cells separate at the smallest input changes and drive the separated code onto CA3 through detonator synapses, with lesion and NMDA-receptor-knockout data showing the step is necessary for discrimination and dispensable for undemanding conditioning (Yassa & Stark 2011). Its price is that it de-aliases *everything*, including repeats that should have been recognised, so it only works with a controller (G38). **Now built, two ways, with complementary costs:** a clone-structured hidden Markov model whose per-observation clone pool is frozen at 0/1 and whose transitions are learned by expectation-maximisation — local, fast, one environment, zero transfer ([[wiki/entities/cscg.md]]) — and an action-accumulated latent that de-aliases by *position* and transfers, but is slow to acquire ([[wiki/concepts/path-integration.md]], [[wiki/entities/tolman-eichenbaum-machine.md]]). Merging them is stated as the obvious next model and not yet done. **Fifth answer, and the only one that is not a computation at all:** *randomization* — the mossy-fibre projection (~46 inputs per CA3 cell) destroys the input's similarity structure and hands the store a random address, so any two events pick near-orthogonal cell sets with no decision, no threshold and no learned code (Rolls 2013). It is confined to the write path precisely because it cannot recognise a repeat, which is what makes the anatomically separate read port necessary rather than merely convenient. **Sixth answer — randomization moved one stage earlier and made exponential** ([[wiki/entities/vector-hash.md]]): a *fixed random* projection from a prestructured grid code into the store, with any pointwise nonlinearity (rectification suffices; a linear layer fails), makes the store's state set strongly full rank, so every one of exponentially many positions is a distinct, error-correcting address and new environments de-alias against all previous ones by taking a random initial phase. Unlike the mossy-fibre version it *can* be read as well as written, because the address is regenerated by the grid dynamics from a partial cue rather than re-hashed
