# G49 — No store schedules its own reads, and none has a relevance-addressed erase

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A store prepares an item for a query before the query arrives, and erases by relevance rather than by age or usage, with both scheduled by the controller and not by a fixed policy.

## Why it blocks the target

Fast **M** is specified with two primitives — write and read-on-demand — and forgetting is a time constant or an eviction policy. Prefrontal cortex runs three: information is *made ready* several hundred milliseconds before it is queried, for the specific item about to be queried and no other; the read is cancelled when an earlier result makes the query unnecessary; and when content stops mattering an inhibitory signal is delivered **to the sites that hold it**, dropping their information while sites holding nothing are unaffected. A store without the first cannot meet a deadline, without the second wastes its read budget on items it will not use, and without the third can only recover capacity by waiting (Lundqvist et al. 2018)

## Best current answer

Nothing implements the schedule. The closest read-side machinery is [[wiki/entities/differentiable-neural-computer.md]]'s free list plus temporal-link matrix, which frees by *usage* and orders by write time, neither of which is relevance; [[wiki/entities/pbwm.md]] learns a write gate by reinforcement and leaves the read ungated; softmax attention recomputes selection from the current query and therefore cannot prepare anything in advance ([[wiki/concepts/attention.md]]). The biological controller's output format is known — an item address plus a lead time — and its policy is not. **And the erase is not one primitive but a typed family**: replacing an item, suppressing one while the buffer stays occupied, and clearing the buffer entirely are separable in cortical representation, with only the frontoparietal control network distinguishing all three from maintenance (DeRosa et al. 2024). The wiki's stores implement `replace` and a usage-driven approximation of `clear`; none implements `suppress` — a targeted removal not triggered by an incoming item needing the space — and none carries an operation *type* at all. **One store now moves the erase half, and it moves it further than the row asks** (Casanueva-Morato et al. 2024, [[wiki/entities/spiking-hippocampal-cam.md]]): the erase is never issued — writing a memory onto an occupied cue makes that cue recall its old content one step into the 3-step write window, which is post-before-pre for the `cue→content` synapses and therefore depresses exactly the old associations; and the units shared with the *new* memory are refractory when the depressing volley arrives, so the erase lands on `old \ new` with no comparison, no mask and no bookkeeping. Two things this settles and one it does not. The address is right (the overwritten cue) and the selectivity is computed by a membrane time constant rather than by a controller, which is cheaper than any relevance signal the row was looking for. The *operation type* is also recovered — from a 1 ms delay differential between the cue and content input volleys, inside the carrier, contradicting the DeRosa reading that the type is control-layer information that never reaches the store. What is untouched: this is still `replace` (relevance means only "shares my cue"), there is no `suppress`, and the read has no schedule at all — every operation is a fixed 6–7 step pipeline on a global clock **And the erase half now has a differentiable, provably-targeted form** ([[wiki/concepts/fast-weight-programming.md]], Schlag et al. 2021): in an outer-product store, read the value currently at the incoming key (`v̄ = Wφ(k)`), subtract it, and write the interpolant — `W ← W + β(v − v̄) ⊗ φ(k)`, the Widrow–Hoff delta rule with a learned per-step rate `β = σ(W_β x)`. The proof is the point: for any association whose key is orthogonal to `k`, `W'k₁ = v₁` **exactly**, where the concurrently-proposed gated rule `(1−β)W + βv⊗φ(k)` gives `(1−β)v₁` — i.e. a global decay of the whole store dressed as a targeted write, which is this row's complaint about eviction policies restated in one line of algebra. Two things it adds. The address is right and costs one extra read plus one row of parameters, with no slots, no free list and no bookkeeping ([[wiki/entities/differentiable-neural-computer.md]] buys the same targeting with all three). And the controller emits a **write strength**, which is a fourth field on the same channel as address, lead time and removal type, and the only one anything here learns end-to-end — though it is conditioned on the current token alone, so in the first layer the write is decided with no context. What is untouched: still `replace` only, with relevance meaning "shares my key"; `β = 1, v = 0` cannot be distinguished from binding the key to zero, so there is no `suppress` and no capacity is reclaimed; and the read remains a pure function of the current query with no schedule whatsoever
