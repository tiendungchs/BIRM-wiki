# G73 — Nothing constructs a problem representation; every architecture is handed one

**Status:** `OPEN`  
**Kind:** `part`  
**Level:** `L0`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A system constructs a problem representation — deciding what is relevant and what relates to what — for a task whose representation type was not fixed in advance. `G75` is the parse-specific case.

## Why it blocks the target

Solving decomposes into *framing* — deciding which aspects of a situation are relevant and what relates them — and optimisation within that frame. Every result in the wiki is the second: a DSL, a grid format, a symbolic state space, an observation encoding or a fixed variable set is supplied, and discovery runs over it. The cost is that the harder half is invisible to every score, and that a system optimising inside a wrong representation has no signal telling it so — it reads as a search that needs more compute

## Best current answer

None. The nearest partial mechanisms each build *one* element of a representation whose type was fixed in advance: [[wiki/concepts/event-segmentation.md]] carves a stream into ⟨precondition, transition, effect⟩ schemas with a hand-thresholded detector (G27), [[wiki/entities/spelkenet.md]] computes the object system's entry test from video rather than declaring it, [[wiki/entities/adaworld.md]] infers a latent action code. [[wiki/entities/arc-agi-3.md]] is the only benchmark here that withholds any part of the framing (the action semantics, the objective) and it still supplies the state space. The only design aimed at the whole thing is a proposal: `N` arbitrary simulated worlds sharing only the property of having regularities, never reused, with human core knowledge deliberately withheld — unimplemented, and with no account of how goal fulfilment is measured in a world nobody has framed (G72)

**One proposal names the missing row's *language* without filling it** ([[wiki/concepts/visual-routines.md]], Ullman 1984). A representation is constructed by compiling a procedure over a fixed, small, task-independent instruction set and running it on an unarticulated base representation; what is made explicit is then a function of the goal rather than of the input, which is exactly this row's "deciding what is relevant and what relates to what". It is the only account in the wiki where the framing is an object with a *grammar* — so the row's demand becomes buildable in principle (synthesise a program over an operation set) rather than open-ended. It closes nothing: there is no implementation, the operation set is offered as plausible rather than sufficient, and the assembly mechanism — the part that would do the constructing — is left as an open problem by its own author.

**And the one system in the wiki whose representation is genuinely a function of the moment — which sharpens the row rather than closing it** ([[wiki/concepts/active-vision.md]], Ballard et al. 1997). Deictic binding makes the representation *transient by construction*: two or three pointers bound to locations in the world, holding only what the current step reads through them, rebuilt every ~0.3 s and discarded. Measured, the same fixated location yields a colour at one step of a block-copying task and a relative offset at another, and what survives a saccade is set by task phase and not by the display. So "what is relevant right now" is answered per step, by the program, at a price the paper counts (a nondeictic alternative that catalogues each block with a unique identifier would need **43 billion** relationships for configurations of 20 blocks).

Two things this does to the row. It supplies the **missing cost argument**: a constructed representation is not merely hard to produce, a *persistent* one is combinatorially unaffordable, which is an argument for building the framing per step rather than once — and the blocks reinforcement learner runs on **16 bits** of state as a result. And it **relocates the residue precisely**. The pointers are bound dynamically; the *feature set they read through* (`fixated-colour`, `fixated-stack-height`, `table-below-fixation-point`, …) was chosen by the authors, as was the 14-action repertoire. So the row's demand survives intact one level down: deixis shows that a small task-indexed representation suffices and supplies no mechanism that would have produced the vocabulary it indexes into. It also names a hazard the row should carry — a reduced deictic state **aliases** (with fixation alone, "fixating a blue block" is ambiguous between *pick up* and *go look at the green one*), and the paper's only repair is adding a second pointer, which re-enters the `(MV)^s` search cost deixis existed to avoid.
