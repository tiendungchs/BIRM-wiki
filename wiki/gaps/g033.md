# G33 — Nothing decomposes a task into subgoals

**Status:** `PARTIAL`  
**Kind:** `part`  
**Level:** `L0`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A configurator selects a subgoal sequence from the world model's own state, on a task whose decomposition was never demonstrated, and beats a flat planner given the same budget.

## Why it blocks the target

Hierarchical planning is now mechanised down to one missing step: a high-level action can be a *condition on the lower-level state* ([[wiki/entities/h-jepa.md]]), so subgoals need no symbolic vocabulary — but something must decide *which sequence of subgoals* a complex task becomes, and configure the cost module for each in turn. This is also the read half of G15 at a second level: not "when to plan" but "plan toward what"

## Best current answer

None. LeCun 2022 assigns the job to a **configurator** module, describes its interface precisely (modulate parameters and attention circuits of perception, world model and cost; extra input tokens in transformer modules), calls it "the most mysterious" part of the architecture, and leaves the decomposition itself "open for future investigation". Hierarchical reinforcement learning has been attacking the same question for longer and offers five partial answers, none settled: subgoals as innate/evolved primitives; states recurring in *rewarded* trajectories; **access points found by partitioning the estimated transition graph** (the only family that needs no signal the graph does not already contain); intrinsic reward for making unexpected salient events recur; and subgoals imported from an impasse or from watching another agent. The same source supplies the cost of getting it wrong — a wrong option set does not merely slow learning, it can make the optimal path unreachable (Botvinick, Niv & Barto 2009). **A sixth family is now built and measured** ([[wiki/entities/hisd.md]]): symbolise unlabelled observation trajectories by optimal-transport segmentation, compress the corpus with a grammar, and keep every rule the corpus uses twice — subgoals by *recurrence* rather than by bottleneck-ness, requiring no reward, no actions, no interaction and no transition graph, and producing the option-of-options nesting the options framework permits but never constructs. It is also the first evidence that the decomposition itself pays: with the discovered skill set held fixed, making the composite nodes selectable beats using the same skills flat, and both beat primitive-action PPO, which fails the task. What it does not supply is a *task-conditioned* decomposition — the grammar is induced once over a demonstration corpus, not configured per goal at query time (Harvey et al. 2026). **The graph-partitioning family is also built now, and it is the first decomposition in this row shown to beat its own flat baseline on path length** ([[wiki/entities/cscg.md]], George et al. 2021): InfoMap over a clone-structured hidden Markov model's learned transition matrix returns communities that never straddle the true rooms, a second pass returns the hyper-rooms, and top-down planning through the two levels gives paths 25% shorter than flat Dijkstra while size-matched surrogate communities that ignore room boundaries give paths 35% longer — so the benefit is attributable to the partition rather than to hierarchy as such. Its control adds a prerequisite this row did not state: the same partitioner on a successor representation over the *raw aliased observations* recovers nothing, so this family needs a de-aliaser upstream and not merely a transition estimate. Two things it still leaves to the experimenter: the number of levels is how many times the partitioner is re-run, and re-partitioning is never scheduled — a shortcut discovered after the decomposition was computed stays invisible to it. **The cost of leaving this to the experimenter is now visible on hardware** ([[wiki/entities/v-jepa-2.md]]): V-JEPA 2-AC solves real-robot pick-and-place from three hand-chosen goal images on a fixed 4/10/4 step timetable with no achievement detector, and this is exactly what reduces the planner to **horizon 1** — so the missing decomposition is not a convenience being substituted for, it is *search depth* being substituted for, and the source lists the un-decomposed version as a task it cannot do. It also shows the cheapest possible subgoal representation: not a symbol and not a learned cost but an *image*, whose embedding under the already-trained encoder is the thing descended toward

**The row has been missing an *objective*, and now has one** ([[wiki/concepts/optimal-hierarchy-criterion.md]], Solway et al. 2014). An option inventory is a model of the behaviours the agent must produce; its Bayesian model evidence over a task ensemble is provably equal, up to argmax, to both the shortest code length for those behaviours and the smallest geometric-mean number of trial-and-error attempts needed to discover the optimal policy of a randomly drawn task or subtask. The mechanism is that a good decomposition absorbs constraint into reusable option policies and leaves the *root* policy unconstrained wherever an option is running, and that multiplicity is what raises the marginal likelihood. The optimum lands on topological bottlenecks — four-rooms doorways, and for the Tower of Hanoi the three positions of the largest disk — which is the first normative licence for the graph-partitioning family this row already leans on, and it makes the row's seven families commensurable as description-length minimisers differing only in which stream they code. Four human experiments (`n` = 40, 10, 21, 35) show people find that parse with no prompt and from local adjacency alone (degree, exposure and salience equalised; bottleneck vertices chosen 4.4× chance rate) and plan through it region-first (faster correct RTs at boundary probes; equal-length Tower of Hanoi paths split by boundary-crossing count). **What it does not do is close the row**, and the reason is precise: the criterion's *data are the already-optimal flat policies for the whole ensemble*, so it scores a decomposition that presupposes the tasks are solved rather than selecting one from the world model's own state, which is exactly what `Closes when` demands. It also assumes the task ensemble is given, needs a deterministic reversible tabular graph, is only ever computed one level deep, returns ties on symmetric graphs, and is cheap to evaluate but expensive to maximise (search over all edge on/off partitions, run as binary integer programming under a genetic algorithm with up to 1000 restarts). The authors explicitly deny that humans compute it and nominate ordinary predictive learning ([[wiki/concepts/successor-representation.md]]) as the approximator — untested against their own four experiments
