# G69 — No architecture creates variables on demand

**Status:** `PARTIAL`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** An architecture mints a variable with persistent identity on first mention and caches its properties thereafter, outside a declared variable set and outside a Bayesian formalism.

## Why it blocks the target

Productivity in the PLoT sense is *unbounded random-variable creation with persistent identity*: an individual is minted at first mention (`gensym`) and its properties are sampled once and cached thereafter (`mem`), so one program specifies infinitely many Bayes nets. Every architecture in the wiki instead fixes its variable set in advance — a Bayes net's nodes, a graph network's node set, an attractor network's units, a transformer's slots — so representing a novel individual means either reusing a slot or retraining. Without it, a reasoner cannot represent "a player whose strength I have not yet estimated" at all, which is what the tug-of-war fits require and what generalisation to a new entity in a known domain always requires

## Best current answer

**Partial, and only in Bayesian formalisms.** [[wiki/entities/coin-model.md]] infers the *number* of latent contexts, so its lower level is unbounded; [[wiki/entities/hbtom.md]] instantiates per-agent parameters but over a declared agent set. `mem` is operationally an allocation-on-demand associative store keyed by an identity token, which is the same primitive as [[wiki/concepts/memory-allocation-excitability.md]]'s allocation problem stated in a symbolic vocabulary — nobody has connected them. No connectionist architecture here does it. **A second partial, and the first where the count is set by the data rather than declared** ([[wiki/entities/autotom.md]]): mental variables are instantiated per timestep only when adding one raises the query's model utility, and the number of timesteps is itself grown backwards on demand, so the variable count of the final Bayes net is a function of the question and the context and is not knowable in advance. The distance still to go is exactly `gensym`: the *types* come from a four-item authored menu, and an instantiated variable is addressed by (agent, timestep, type) rather than by a minted identity, so a second entity of the same type at the same time is no more representable here than under superposition. **And a sharper form of the same gap in a connectionist code.** HRR contextualization individuates fillers by the *roles* they occupy, which works only when no two entities fill the same role set: two boys bitten by two dogs, each fleeing the dog that did *not* bite him, is not distinguishable from the case where each flees the dog that did. So the harder statement is not only that nothing creates variables on demand, but that nothing keeps two variables **of the same type** distinct under superposition.  **And the closest thing to `gensym` in a trained network gets half way and stops** ([[wiki/concepts/multi-token-embedding.md]]): early transformer MLPs compute a scattered representation for *any* combination of name tokens — the addressing is total, and works on entities never seen — but a value sits behind that address only for entities present in training, and no write is available at inference. So a novel individual is *individuated* and cannot be *populated*, which is the gap's two halves separated for the first time: allocation is solved by a learned hash, binding of new properties to the allocated slot is not.
