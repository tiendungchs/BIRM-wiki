# G60 — Every architecture derives its retrieval query from the goal; none chooses the query

**Status:** `OPEN`  
**Kind:** `part`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** _unset — see [[wiki/priority-tasks.md]]_

## Why it blocks the target

Attention, retrieval-augmented models, glimpse policies and the wiki's own priority map all set `q = encode(goal)`, so the query is a deterministic function of what is wanted. Biology treats it as a decision: after a face cue whose target is hard to discriminate, the human template network (inferior frontal junction, parietal eye fields) and the associate's own category area hold a *learned scene associate over an 8 s delay* while the target face is decodable in no template region, and the associate is dropped when the target is easy to discriminate. The register is loaded with whatever maximises expected guidance value — predictive validity × detectability — over the goal's associative neighbourhood, which is a sub-policy with no slot anywhere in the wiki

## Best current answer

Add three components around any query register: (i) a proposer that enumerates one-edge neighbours of the goal in an associative store, (ii) a scorer combining each candidate's predictive validity for the goal with its detectability under the current input statistics, (iii) a monitor plus reload path, since a proxy that fails cannot be resolved on the fast path — the biological cost is an accuracy drop (`d` = 0.97) and anterior-cingulate-plus-lateral-prefrontal reactive control on exactly those trials. Untested crossover: nobody has varied target discriminability and associate validity independently to find where the swap happens **The row now has a case where an architecture *does* choose its own query, and a measurement of what that costs.** SpelkeNet samples its own intervention sites from a motion-affordance map it computes itself, with no goal anywhere in the loop. Given externally supplied point prompts it beats a supervised segmenter (Average Recall 0.541 vs 0.482); choosing its own it falls below that baseline (0.46 vs 0.62). So the extraction machinery and the query selector are separately scorable, and on the only pair the wiki has, **the selector is the weaker component by a wide margin** — its proposer is a threshold, its scorer is uniform sampling, and it has no monitor (Venkatesh et al. 2025, [[wiki/entities/spelkenet.md]]). **The closest thing to a query-choice mechanism in the wiki, and it is a knob rather than a policy.** In a contextualized HRR store, changing the mixing weights of the *probe* alone changes what similarity means — an uncontextualized probe against the same memory reproduces a surface-driven ranking, a contextualized one reproduces the structure-sensitive ranking — so the query is genuinely a free variable that is not a function of the goal. What is missing is exactly (ii) and (iii): nothing scores which weighting to use, and nothing detects that the chosen one failed.
