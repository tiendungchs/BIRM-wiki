# G46 — Nothing predicts the *order* in which a learner disambiguates its aliased states

**Status:** `OPEN`  
**Kind:** `part`  
**Level:** `L4`  
**Registry:** [[wiki/architectural-gaps.md]]  
**Closes when:** A disambiguation-order prediction survives an input-encoding sweep, so the predicted order is a property of the learner and not of a formatting choice the task leaves free.

## Why it blocks the target

The wiki's models are compared at convergence, and at convergence they are not distinguishable: on one aliased task, a clone-structured hidden Markov model, a softmax recurrent network and a spiking Hebbian network all reach the same orthogonalized endpoint that mouse CA1 reaches. The learning *trajectory* does distinguish them — CA1 separates the within-track ambiguous regions first, then the pre-far-reward region, then the pre-near-reward region, and only the clone model reproduces that order (Sun et al. 2025). This matters beyond model selection: the order is the schedule on which a system's node set becomes trustworthy, so an agent acting mid-learning is acting on a partly-merged graph and nothing says which merges are still live

## Best current answer

Only one model matches, and its match is one input-format decision deep: presenting the water symbol before rather than after the reward-zone visual symbol leaves the learned transition graph identical and **inverts** the predicted order. So the wiki has no account of the order that is robust to a choice the task does not fix. The generalisation this demands is an encoding sweep — perturb the input representation over the range a modeller could defensibly have chosen and report the fraction of encodings that preserve the match — and no source in the wiki reports one
