# T55 — Should a fast store's addressing be random, or should it follow the data?

**Status:** `LIVE`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** _unset — see [[wiki/priority-tasks.md]]_

## Position A

**Random, and deliberately so.** Randomisation is what makes codes non-overlapping without any statistics of the input: dentate mossy-fibre hashing hands CA3 an effectively random address ([[wiki/entities/rolls-treves-hippocampal-model.md]]), and a fixed random projection of a prestructured grid code yields provably convex, equal-sized, spurious-free basins ([[wiki/entities/vector-hash.md]]). The benefit is that it assumes nothing about the data and cannot be misled by it

## Position B

**Random addressing is optimal only for *uniform* data, and real data clusters.** With clustered data a uniformly-sampled address set leaves most locations never activated (wasted) while a few are written repeatedly until their contents are noise; the measured fixes are all data-dependent — hard addresses sampled from the data address distribution (best NETtalk results; "dramatic" improvement on spoken digits), self-organising-map placement, per-location activation radii `H_m`, or per-cue weighted Hamming distance — and the optimal active fraction is itself *smaller* under clustering than the uniform formula gives (Kanerva 1993, [[wiki/entities/sparse-distributed-memory.md]])

## Where it bites

Whether the addressing stage of a fast store may stay frozen at initialisation. If B holds generally, Vector-HaSH's exponential capacity and Rolls–Treves' randomisation argument are results about *uniformly spread* content, and any real content distribution costs a fraction of the store that nobody has measured. Two reconciliations: (i) the codes being hashed in both A cases are already near-uniform (grid phases; sparse DG output), so the clustering B worries about was removed upstream — which relocates the problem to whatever produces that code rather than dissolving it; (ii) A's stores address by a *structural* variable and B's by content, and only content clusters
