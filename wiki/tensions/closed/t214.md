# T214 — What is the human baseline on ConceptARC?

**Status:** `RESOLVED/LIVE`  
**Level:** `L4`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** A machine 3-attempt score on ConceptARC is reported, so the ~91% figure has a commensurable counterpart; `pass@1` already has 73%.

## Position A

**~91% mean per-concept.** 415 participants, 8–14 per test input, three attempts each, averaged over participants per test input and then over the 16 concept groups — 0.83–0.97 across concepts, and the number the benchmark's founding 40-point human−machine gap is measured against ([[wiki/entities/conceptarc.md]])

## Position B

**73% `pass@1`.** Beger et al. 2025 re-analyse the *same* study's unpublished per-response data on the same 480 items and report first-attempt accuracy, which is below o3's 75.6–77.1% textual accuracy and below o4-mini's 77.7%

## Where it bites

Every "models now match/exceed humans on ConceptARC" claim, and the direction of the gap this benchmark exists to report. The two numbers are not in conflict about the world — three attempts versus one, per-concept mean versus per-item pooled — but they license opposite headlines, and only the second is commensurable with a machine `pass@1`. It is T213's defect recurring on the sister benchmark, and here the fix has already been paid for: the raw data supports both, so any paper using either should state which **Root cause:** attempt budget (B2) left unstated, the parameter that most often breaks commensurability because machine scores are almost always `pass@1` — [[wiki/concepts/human-baseline.md]].

## Status

`RESOLVED` as a protocol difference, `LIVE` as a reporting defect — the wiki should quote 73% against machine `pass@1` and ~91% only against a 3-attempt machine score, and no source reports the latter
