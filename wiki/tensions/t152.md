# T152 — Is a world model's conditioning interface a design requirement, or an implementation detail?

**Status:** `LEANING`  
**Level:** `L2`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** The diffusion alternative is run as a baseline on localised counterfactual probing — the interface argument is currently a priori with one demonstration behind it.

## Position A

**An implementation detail.** Every world model in the wiki is specified as architecture + objective + data (+ behaviour policy, after Zhang et al. 2026), and the conditioning path — text prompt, dense mask, action vector, goal embedding — is chosen for convenience. The evaluation follows: prediction quality, then planning success

## Position B

**A requirement, and it gates which counterfactuals exist.** Diffusion's iterative *global* denoising has no place to put a one-pixel intervention, and text is a poor control surface for fine-grained spatial queries — so both are excluded from counterfactual probing however accurate they are. LRAS's `(pointer, content)` token pairing makes a localised intervention two appended tokens and arbitrary decoding order a posterior-exploration knob, which is the stated reason SpelkeNet is built on it rather than on a video diffusion model (Venkatesh et al. 2025)

## Where it bites

Model selection for anything other than open-loop prediction. If B holds, a model's *query language* is a first-class property, an accurate model with a global-only interface answers no interventional question, and the literature's architectural comparisons (JEPA vs RSSM vs diffusion) are missing an axis

## Status

`LEANING` — toward B, on one demonstration: the interface argument is stated a priori and the diffusion alternative was never run as a baseline
