# T10 — Is an innate prior architecturally necessary, or just knowledge delivered early?

**Status:** `LIVE`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** _unset — see [[wiki/priority-tasks.md]]_

## Position A

**Necessary.** Core knowledge is a bank of domain-specific, entry-gated systems that guide learning top-down from the start; without them the learner has no `g`-side prior at all and the intended graph is unidentifiable ([[wiki/concepts/core-knowledge.md]], gap G16)

## Position B

**Not necessary.** For an ideal inductor, knowledge `z` presented as the *first observation* replaces `K(µ)` by `K(µ|z)` in the convergence bounds; as long as the code interpreting `z` is `O(1)`, the agent absorbs it within a few cycles — so "the boundary between implementation and training is unsharp", and innateness is a claim about *timing*, not architecture (Hutter 2000)

## Where it bites

Decides whether priors must be built into the architecture or can be supplied as data/context. If B holds at realistic scale, prompting and pretraining are substitutes for architectural priors; if A holds, they are not

## Status

`LIVE` — B's equivalence is asymptotic and assumes an `O(1)` interpreter and an agent that can already compress arbitrary input, which is precisely what a bounded learner lacks. The same source supplies A's strongest argument: if evolution encoded something `Ω`-like and incompressible into the genome, no `O(1)` program reaches human competence and the missing part is exactly the installed prior
