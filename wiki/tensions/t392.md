# T392 — Is forgetting the loss of a trace, or the loss of its address?

**Status:** `LIVE`  
**Level:** `L1`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** One store is run past capacity and then probed for the *presence* of the overwritten items by a mechanism that does not know which items they were — recovering them shows the trace survived and the store needs no erase operator; failing to recover them under any gain setting shows removal is a primitive the decomposition must contain.

## Position A

**Retrieval failure. The trace is not removed.** Behaviourally: list-before-last recall depends on the length of the list *being recalled*, not on the intervening list, so new items do not displace old ones (Shiffrin); over a retention interval **accessibility** declines while **precision** does not, so memories vanish whole and return sharp (Berens et al.); retrograde amnesia shrinks, protein-synthesis amnesia recovers on delayed test and can be reversed by the amnestic agent itself; extinction is followed by spontaneous recovery. Formally: a linear layer trained by gradient descent *is* a key-value store whose keys are its inputs and whose values are its error signals, so it provably retains every training pair — and multiplying the keys of a catastrophically forgotten task by a scalar `β ≥ 1` restores 99% task accuracy with no retraining and no access to that task's data ([[wiki/concepts/key-value-memory.md]], Gershman, Fiete & Irie 2025)

## Position B

**Erasure. Removal is a primitive the store executes.** The wiki's fast stores do not merely lose addressing: the `(1 − η)` factor of a slot write **zeroes exactly the synapses the write then fills**, so the previous occupant is gone and the retention window is set by the allocation rate ([[wiki/entities/three-factor-key-value-memory.md]]); past capacity a Hopfield store suffers blackout in which the energy landscape itself is destroyed, not merely crowded ([[wiki/entities/hopfield-network.md]]); prefrontal cortex runs a *typed family* of removal operations — suppress one item, clear the buffer, replace — that are separable in cortical representational geometry, which is an odd thing for a system whose only failure mode is addressing ([[wiki/concepts/memory-read-and-erase.md]]); and hippocampal indexing theory makes reversible depotentiation of the index its **designed** forgetting mechanism rather than an accident ([[wiki/concepts/hippocampal-indexing-theory.md]])

## Where it bites

Whether the decomposition needs an erase block at all. Under A the fast store has one write and no delete, capacity failures are addressing failures, and the entire eviction/forgetting-rate hole that `G42` keeps reporting is the wrong question — what is missing is a *query policy*, not a retention policy. Under B a store must decide what to remove and when, and `G49`'s relevance-addressed erase is load-bearing. The two give opposite advice on continual learning: A says train freely and fix retrieval afterwards, B says protect the weights because what is overwritten is gone.

The positions may also be separated by **decomposition rather than by fact**: superposed stores (A's linear layer, an outer-product matrix) never delete because addition is not destructive, while slot stores (B's key-value network) delete because a slot has one occupant. If that is the whole disagreement, the row resolves into a design choice with a stated price — superposition retains everything and degrades addressing, slotting addresses cleanly and destroys.

## Status

`LIVE` — Position A's formal half is an identity and holds for the case it covers (additive linear layers); its behavioural half is an argument from recoveries that do not establish that nothing is lost, and the `β` demonstration uses an experimenter-supplied label for which keys to amplify, so it shows presence rather than recoverability. Position B's mechanisms are explicit in running code but none has been probed for residual traces after overwrite.
