# T321 — Does a per-input compute budget buy anything on language modelling?

**Status:** `LIVE`  
**Level:** `L3`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** One halting mechanism is run on both a character-level and a broad-context word-level language-modelling task with depth-matched fixed-compute controls on each, and either the gain appears on both (B wins, the demand-uniformity explanation is wrong) or it appears only where the target word depends on distant discourse (A wins, with the boundary drawn at what the halting decision can be *about*).

## Position A

**Nothing to allocate.** Graves 2016 attaches ACT to an LSTM on Hutter-prize Wikipedia character prediction: error essentially unchanged, learning curves only slightly more data-efficient, and ponder per input much lower than on the four synthetic tasks where ACT worked ([[wiki/concepts/adaptive-computation-time.md]]). The stated reading, which the wiki adopted: where the per-input computational demand is roughly uniform, a per-input budget has nothing to allocate. The four tasks where ACT paid — parity, logic, addition, sort — all have a difficulty parameter that varies by an order of magnitude *within* the task.

## Position B

**A 2.2× perplexity reduction, with the depth explanation controlled out.** [[wiki/entities/universal-transformer.md]] on LAMBADA language modelling: fixed 6 steps 319 test perplexity, fixed 8 steps 202, fixed 9 steps 239, dynamic halting **142** at a measured average of 8.2 ± 2.1 steps. So the dynamic model beats every fixed model at or above its own average depth, and the gain is not "it ran longer". Reading comprehension on the same data moves 0.5216 → 0.5625. The authors attribute it to halting acting as a **regulariser** — a smaller budget forced on some symbols so more is affordable for others — which is a different mechanism from allocation-by-difficulty and would predict gains even where demand *is* uniform.

## Where it bites

On whether a compute-allocating architecture is worth building for natural language at all, and on `G107`. If A holds, halting is a synthetic-task and multi-hop-reasoning device, the bAbI supporting-fact scaling (2.3/3.1/3.8) is the real signal, and the price constant only needs solving where difficulty is heterogeneous. If B holds, the benefit is partly *regularisation* rather than *allocation* — in which case the wiki's whole reading of ponder time as a forward-looking measure of reducible structure is over-attributed, and the correct control for every future halting result is a depth-matched fixed model, which almost nobody runs.

The two are not cleanly opposed on task type either: LAMBADA is constructed so the target word is predictable only from several preceding sentences, i.e. it is a *selected* subset where demand is maximally non-uniform, while Hutter Wikipedia is unfiltered. So A's explanation survives if "language modelling" is disaggregated — and then the negative result is about the corpus, not the objective. Cutting against that: UT's control set (LAMBADA-like passages with no filtering, i.e. ordinary LM) also improves, 131 → 130 perplexity and 0.32 accuracy — a much smaller move, which is weak evidence for A inside B's own table.

## Status

`LIVE` — different architectures (LSTM vs. depth-recurrent Transformer), different halting granularity (per input step vs. per position), different stop pressure (ponder penalty `τ` vs. bare threshold) and different corpora, so no single variable is isolated. The strongest evidence for B is a control Graves never ran (depth-matched fixed compute); the strongest evidence for A is a corpus UT never ran on.
