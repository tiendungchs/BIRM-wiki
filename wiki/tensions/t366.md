# T366 — Does widening the training goal set help the one task you care about, or destroy it?

**Status:** `LIVE`  
**Level:** `L0`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** One learner, one architecture and one interaction budget are run with the training distribution widened in two ways on the same evaluation task — by adding *goals inside one task's goal space* and by adding *whole tasks* — showing whether the sign of the effect is set by the count of training objectives or by whether the added objectives share the evaluation task's latent variables.

## Position A

**Widening helps, even when only one goal is wanted.** With the goal state identical in every episode, DDPG+HER still beats DDPG on pushing, sliding and pick-and-place; and comparing the single-goal runs against the multi-goal runs, the *same* agent learns **faster when episodes contain many different goals** than when they contain only the one being evaluated. The authors' stated conclusion is that it is advisable to train on multiple goals even if only one is cared about (Andrychowicz et al. 2017, [[wiki/concepts/hindsight-goal-relabelling.md]]; the same effect is reported by Pinto & Gupta 2016).

## Position B

**Widening can remove a capability outright.** In IRENE, training on the Multi-Agent task alone gives 51.5 (chance); adding the unrelated Preference task raises Multi-Agent to **80.4**, the best score in the study; adding a third unrelated task (Instrumental) drops it back to **51.4**. Dropping a task can also *raise* an average (MPS → 80.4 vs the full set's 71.5). The training-objective count is non-monotone in both directions ([[wiki/entities/irene.md]]).

## Where it bites

Every self-generated-goal design in the wiki assumes more goals is more signal — the competence-based intrinsic-motivation family ([[wiki/concepts/intrinsic-motivation-typology.md]]), eigenoption libraries sized by an experimenter's `k` ([[wiki/concepts/eigenoption-discovery.md]]), and hindsight relabelling itself, whose `k > 8` degradation is already a measured instance of *too many* relabelled objectives. If B is the general case, a goal generator needs an **admission criterion**, not just a sampler, and `G72`'s "infer what to want" acquires a second half: infer what *not* to train on.

The cheapest candidate resolution, and it is a distinction neither source draws: A widens **within one goal space over one dynamics** (every Fetch goal is a box position under the same physics, so a relabelled goal is extra supervision on a shared transition model), while B widens **across goal spaces with disjoint latent variables** (barrier knowledge, key-lock structure). That predicts the sign flips not with the number of objectives but with whether the added objective exercises the same latent variables as the evaluation task — testable directly, and unrun.

## Status

`LIVE` — no source runs both manipulations. Position A's effect is measured on a learner whose relabelling mechanism *requires* goal-space sharing, so it cannot produce B's regime; Position B's tasks share an environment and a renderer but not their causal structure, so it cannot produce A's.
