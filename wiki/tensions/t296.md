# T296 — Does a sparse expert router have to be learned, or is a fixed random partition of the input enough?

**Status:** `LIVE`  
**Level:** `L3`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** A learned router and a hash router are compared at matched compute on a task whose correct expert assignment is *context-dependent* — i.e. where the same token must go to different experts in different contexts — and the learned router's margin is reported.

## Position A

**The router is the architecture.** The entire sparse-expert literature treats routing as the object of study: differentiable top-`k` weighted by the router probability ([[wiki/entities/sparsely-gated-moe.md]], Shazeer et al. 2017), REINFORCE over expert selection (Bengio et al. 2015, Clark et al. 2022), linear assignment (BASE) and optimal transport (S-BASE), expert-choice routing (Zhou et al. 2022), dense-to-sparse annealing (DTS-Gate), smooth top-`k` (DSelect-k). Auxiliary balance losses, the router z-loss and float32 router precision all exist to make the *learned* decision behave. Expert specialisation is then observed — quantities, punctuation, verbs, textures, eyes, wheels — and read as evidence that the router discovered a decomposition (Fedus, Dean & Zoph 2022, [[wiki/concepts/sparse-expert-routing.md]])

## Position B

**Most of the win is the sparsity, not the routing.** Hash Layers (Roller et al. 2021) route by a **fixed hash of the input token id**, chosen before training only to balance load, with no learning and no context — and reach performance competitive with learned routing. THOR (Zuo et al. 2021) selects two experts **uniformly at random** at training *and* inference and gains 2 BLEU over standard MoE. DEMix and language-specific sublayers route by a hand-declared domain or language label. If a partition chosen by a hash function performs like one optimised end-to-end, then what the parameter expansion buys is capacity at fixed FLOPs, and the router is a load-balancer

## Where it bites

Directly on `G12` and `T283`. The wiki wants a router that selects among *structure types* at query time — a decision that is by definition context-dependent, since the same input can demand a metric or a relational treatment depending on the query. Position B says the only routers anyone has measured at scale might be doing nothing of the kind: a hash is a function of token identity alone, so if it matches a learned router, the learned router was also approximately a function of token identity, and the reported specialisations (which key on the *preceding* token, or on lexical class) are consistent with exactly that. The choice also has opposite cost curves — a hash router is free, has no instability, needs no balance loss and no z-loss, and cannot be blamed for a divergence; a learned router costs a training signal, a numerical-precision problem and a collapse mode

## Status

`LIVE — never tested where it would separate, and now with an architecture that would settle it if anyone ran the control.` Every comparison reported in the survey is on language modelling or translation, where token identity predicts the useful expert well and both positions therefore predict the same result. The discriminating experiment is stated in `Closes when` and is cheap: construct or select a task in which the correct expert for a token depends on context, and check whether the hash router's competitiveness survives. The survey's own interpretability caveat is what makes this urgent — the routed embedding already carries self-attention context, so the published specialisation tables *cannot* distinguish a context-sensitive router from a lexical one, and Position B has never been ruled out by the evidence usually cited against it

**Update (Goyal et al. 2019, [[wiki/entities/rims.md]]).** The one system in the wiki whose router satisfies this row's `Closes when` *by construction*: the selection query is computed from each module's own recurrent hidden state, so the same input necessarily routes differently in different contexts — no appeal to self-attention context in the embedding is required, and the interpretability caveat that makes the published specialisation tables undecidable does not apply. Its ablations support Position A at module granularity: removing input attention degrades Atari substantially, and removing inter-module communication breaks training outright. **But the discriminating control is still missing, and the paper's own table cuts the other way.** There is no random-`k_A` variant anywhere (the THOR manoeuvre), and in the copying ablation a **single** module with no input attention and no modularity reaches 0.2 test cross-entropy — better than *every* configuration with input attention and no communication, and better than the six-module no-attention variant. What that single-module variant retains is a residual self-attention path, which is also the paper's own unexcluded alternative explanation for the long-span wins (inactive modules pass state forward by identity, so a 200-step dormant span is a skip connection). So the strongest available evidence that a learned, provably context-dependent router beats a fixed one comes from a source whose ablation table is equally consistent with Position B.
