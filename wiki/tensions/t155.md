# T155 — Does a simplicity prior select structure, or destroy it? *(absorbs T182, "does compression build the library or destroy it?", merged at the 284-source duplicate audit: the two rows asked one question over one measurement.)*

**Status:** `LIVE`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** The decidable version is run: hold the executor's sharing fixed and sweep `λ` against codebook size on one domain, establishing the band's width rather than three points.

## Position A

**Selects — and it is the wiki's oldest bias.** Weight hypotheses by `2^−l(π)` and the mixture dominates every computable alternative ([[wiki/concepts/universal-induction.md]]); [[wiki/concepts/prediction-compression-equivalence.md]] makes log-loss a measure of structure found; the two-level hierarchy is itself an MDL argument (`|primitives| + N·|arrangement|` beats `N·|concept|`, [[wiki/concepts/compositionality.md]]). *Shorter is more compositional* is the premise [[wiki/entities/neo-neural-theorizer.md]] states outright and builds on. **The constructive form of A is library learning**: DreamCoder abstracts program components *shared across previously solved tasks* into new primitives — heuristic hierarchical Bayesian inference of the prior itself, reported to dramatically expand the repertoire of learnable concepts at fixed compute (Ellis et al. 2021; LAPS adds language as a second channel on the same prior, Wong et al. 2022; via Goodman, Gerstenberg & Tenenbaum 2024). It is the only concrete proposal anyone has made for `G26`

## Position B

**Destroys it, past a threshold, and the threshold is close.** The same system sweeps its simplicity weight and reports the reversal: `λ_MDL = 1.2` takes action primitiveness from **1.000 to 0.213** and compositional-OOD transfer from 0.933 to 0.160, with the code–primitive alignment matrix filling with *composite* codes. The mechanism is not subtle — one code for `Left-Down` is a shorter explanation than two codes, so a strong enough length penalty **buys brevity by entangling the vocabulary**, which is the precise opposite of what the bias was invoked for. `λ ∈ {0.8, 1.0}` tracks the ground-truth program length; 1.2 does not. This is the wiki's only *direct* measurement of compression pressure on a learned vocabulary, and it runs against A

## Where it bites

Gap **G26** in its operative form. If short-and-entangled and short-and-compositional are both minima of a length prior, then description length alone never picks the second, and what did the work in the successful runs is *length under enforced re-use* — one shared executor realising every symbol on every instance. That is a second term nobody is pricing, and nothing sets the balance except a sweep against ground truth the learner is not supposed to have. **The two sides may not be measuring the same quantity, which is the merged row's main claim:** A charges description length **across a corpus** (a primitive can only be proposed if it recurs in several solutions), B charges it **within one instance** (free to fuse two primitives that always co-occur in a single solution). If that is the whole difference, both results stand and the rule is that compression must be scored over a corpus, never over an instance — which is the same statement as *length under enforced re-use*, reached from the library side

## Status

`LIVE`. Evidence on B is one sweep of three values in one architecture on three synthetic domains, and `λ` interacts with codebook size (the over-complete run used `λ = 1.0`), so the band's width is unknown; A is second-hand here and reports no primitiveness-style metric at all, and no source runs both regimes on one domain. The decidable version: hold the executor's sharing fixed and vary it — if compositional recovery survives strong length pressure only when the executor is shared across instances, then re-use, not brevity, is the bias worth naming
