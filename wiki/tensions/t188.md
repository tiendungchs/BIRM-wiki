# T188 — Must an induced program be consistent with *all* the demonstrations?

**Status:** `LIVE`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** The `≥2` rule is scored against full consistency on the same task set, with demonstration and query performance reported separately as the VSA solver does.

## Position A

**Yes — consistency with the full data is the criterion.** Every inducer in the wiki scores a hypothesis by its fit to the whole training set: the posterior `p(π|D) ∝ p(D|π)·p(π)` is over the complete `D` ([[wiki/concepts/program-induction.md]]), ARC's own scoring assumes the ~3 demonstration pairs share one program ([[wiki/entities/arc-agi.md]]), and length is used only to break ties *among* fully consistent programs

## Position B

**No — require ≥2, and stop.** [[wiki/entities/ilp-arc-synthesizer.md]] constrains ILP to clauses unifying across two or more training examples and deliberately not all, on the evidence of ARC task `0a938d79`: two pairs demand vertical lines, two horizontal, and the program covering all four is strictly more complex than the one covering the first two — which solves the test. Full coverage bought complexity the test did not need

## Where it bites

Decides what the demonstration set *is*. Under A it is one constraint system and every example is evidence about the same program; under B it is a set of possibly-heterogeneous cases and part of the induction is choosing which of them to explain — a model-selection problem nobody in the wiki has posed. It also changes what a length prior ranks: over-general-but-short and specific-but-long are only comparable once the coverage requirement is fixed

## Status

`LIVE, and A now has a price too` — [[wiki/entities/arc-vsa-solver.md]] reports demonstration and query performance separately for a solver that enforces A in full (its action set must hit every output object of every demonstration): **48.8%** of ARC-AGI-1-Train tasks get a program reproducing every demonstration exactly, **10.8%** solve the query; on Eval, 33.5% → 3.0%. So full consistency with all demonstrations is passed four to eleven times more often than it is right — it is a weak filter, not the criterion A takes it for, and B's objection is no longer only about complexity but about how little the requirement discriminates. B's instance remains unpriced: B's system offers no rule for *which* two examples; the horizontal pair yields an equally valid, equally short program that fails the same test, so the reported success is a 50% draw on a 4-example task and gets worse as the example count grows. What survives regardless is the observation itself: **a fully consistent program can be more complex than the test instance requires**, which no simplicity prior over fully-consistent programs can express, and which is the same complaint as G26 arriving from the data side rather than the prior side
