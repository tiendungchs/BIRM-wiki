# T232 — Within the timing camp, which temporal code actually carries the information — and can the question be settled empirically?

**Status:** `LIVE`  
**Level:** `L3`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** An instrument scores a temporal code independently of its reader, which no source in the wiki has — the question is currently unsettleable rather than unsettled.

## Position A

**Order, not latency: rank-order coding.** Its capacity is combinatorially larger — `log₂(N_spikes!)` bits against a count rate's `log₂(N_spikes + 1)`, six-fold at ten spikes and unbounded thereafter — and it is the only globally-referenced scheme that needs no global reference, because the brain has no access to stimulus onset (Rullen & Thorpe, in Auge et al. 2021). Time-to-first-spike is the engineering favourite and inherits that defect

## Position B

**Neither — count rate wins in the actual measurement.** Rolls, Franco, Aggelopoulos & Jerez analysed spikes in inferior temporal visual cortex and report that count rate in a short window is *fast* and carries **more** information than either time-to-first-spike or rank order, because spontaneous firing corrupts both order and latency. Li & Tsien push a third position: that same spontaneous activity is not noise but inter-spike-interval structure, and rare long silences carry more information than high-activity periods. **And the survey's methodological verdict undercuts all three** — task accuracy cannot arbitrate, since published comparisons vary architecture and learning rule together with the code, while bits-per-spike cannot arbitrate either, because a capacity is only realisable by a reader that can decode it

## Where it bites

Directly under [[wiki/concepts/temporal-coding.md]] and [[wiki/entities/spiking-neural-networks.md]], which argue *that* timing carries content and never say *which* timing variable. It decides what a spiking reasoning architecture should put on its wires, and it sets the terms for gap G77: A's argument for order is an argument from the missing time origin, B's argument against it is an argument from noise. The one clean within-pipeline comparison available goes to latency — same sensor, same network, same task: rank order 95.2%, time-to-first-spike 100%, the loss attributed to jitter permuting near-simultaneous spikes

## Status

`LIVE` — and structurally so: no instrument in the wiki scores a code independently of its reader
