# T18 — Must a world model be generative?

**Status:** `LIVE`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** _unset — see [[wiki/priority-tasks.md]]_

## Position A

**Yes — the model's steps must resemble the generative process.** Causal model building defines a good model as one whose steps correspond to how the data were actually produced; the payoff is the richness criterion (classify, generate, parse, create, explain, re-goal), five of whose six queries require running the model *forward* to produce data (Lake et al. 2017; [[wiki/concepts/causal-model-building.md]])

## Position B

**No — generativity is what prevents abstraction.** A generative model must account for every detail of `y` and can only handle unpredictable detail by pushing it into a latent; it cannot *discard* it, because it has no abstract representation of `y` to discard it from. A joint-embedding architecture predicts the *representation*, so its encoder drops carpet texture and wind-blown leaves outright. "Generative latent-variable models are not capable of eliminating irrelevant details" — hence the explicit recommendation against them for world models (LeCun 2022; [[wiki/entities/h-jepa.md]])

## Where it bites

Decides what the wiki's environment model is for. If A, the model must be invertible into observations and the richness protocol (gap G17) is a valid instrument. If B, a world model is a compatibility function that "cannot easily be used to predict `y` from `x`", four of the six richness queries are unanswerable in principle, and the wiki loses one of its two shift-free evaluation protocols
