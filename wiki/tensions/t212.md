# T212 — Does an LLM's demonstrated analogy competence extend to the ARC domain, or is it bound to the presentation format?

**Status:** `LIVE`  
**Registry:** [[wiki/empirical-tensions.md]]  
**Closes when:** The perception/mapping split is settled by supplying the parse, testing whether the format effect survives when grid reading is free (see T215).

## Position A

**It extends — the competence is general.** Webb et al. 2022 report GPT-3/GPT-4 matching or exceeding human performance zero-shot on several idealized analogy domains, including Copycat-style letter-string analogies, which are *generative* (the answer is constructed, not selected) and are the closest published relative of ARC's task shape `(tentative — second-hand through Moskvichev et al. 2023; the primary is not in raw/)`

## Position B

**It does not.** The same model, prompted in the same style, scores **0.03–0.33 per concept** on [[wiki/entities/conceptarc.md]] — 16 concepts authored to be *easy*, humans at 0.83–0.97 — with every output correctly formatted, so the floor is not a parsing artefact. The gap is not attributable to answer construction (letter-string analogies also construct) nor to few-shot budget (both give demonstrations)

## Where it bites

Whether "LLMs do analogy" is a claim about a mechanism or about a modality. The discriminating variable the wiki can name: ARC grids are **2-D spatial structure serialised into a token sequence**, while letter strings are natively 1-D, so the ConceptARC floor may measure the cost of recovering a spatial parse from row-major text rather than any deficit in analogical mapping. **(brainstorm)** The experiment nobody in the wiki has run: the same tasks presented to the same model as an explicit object list (the parse supplied), which would separate the parse cost from the mapping cost — and which [[wiki/entities/arc-vsa-solver.md]]'s demonstration/query split (48.8 → 10.8) suggests is not the whole story

## Status

`LIVE`, with the wiki's own conjecture now **against** the evidence: Beger et al. 2025 run the same ConceptARC tasks through frontier models in both presentations and the *image* is worse by 40–60 accuracy points (o3 75.6% textual vs 29.2% visual with tools, 5.6% without), with the failure localised to perception rather than mapping ([[wiki/concepts/rule-level-evaluation.md]], T215). So row-major serialisation of 2-D structure is the **cheap** channel for these models, and the ConceptARC floor is not explained by it. The proposed experiment — supply the parse as an explicit object list — is still unrun, and is now the only live way to separate parse cost from mapping cost
